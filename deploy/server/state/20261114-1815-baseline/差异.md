# 基线和"新服务器加固清单"的差异

基线：同目录的 `baseline.txt`（2026-11-14 18:15 在服务器上只读取得，31 个区块，来源和扫描结果见 `meta.txt`）。
清单：知识库《服务器接入与部署方案（2026-11-14）》里的"新服务器加固清单"8 项，后面再加交接清单里和服务器有关的几条，以及基线里碰到的清单以外的事。
括号里的名字是基线里的区块名，方便对照。这个文件夹不进知识库。

## 一眼看结论

1. **只许密钥登录现在不成立**：`sshd -T` 里 `passwordauthentication yes`、`permitrootlogin yes`。是云镜像的 `50-cloud-init.conf` 盖掉了腾讯云绑密钥时加在主文件末尾的 `PasswordAuthentication no`。
2. **自动安全更新现在等于没开**：定时器和服务都在、也在运行，但镜像把允许的来源改成了只有 noble 本体，一条安全更新都不会装；同时有 216 个包待升级。
3. **时间同步已经满足**：chrony 已在跑，配置里就是 `time1` 到 `time5.tencentyun.com`，偏差不到 1 毫秒。脚本草稿原来会重复写一份还注释掉原有的行，已改成不碰。
4. 只开必要端口：对外只有 22；ufw 已装但没启用、没规则。
5. 登录失败封禁：fail2ban 没装；过去 24 小时 ssh 失败登录 0 次。
6. 清单外：服务器上还有一个 `lighthouse` 用户，有免密 sudo。

## 基线里碰到的、清单以外的事

- 系统 Ubuntu 24.04.4 LTS，内核 6.8.0-138，OpenSSH 9.6p1（Ubuntu-3ubuntu13.18），sudo 1.9.15p5；730 个包；失败的服务 0 个；唯一的 root crontab 项是 stargate。
- sshd 是 socket 激活：`ssh.socket` 和 `ssh.service` 都启用，`ssh.socket` 监听 `0.0.0.0:22` 和 `[::]:22`（`BindIPv6Only=ipv6-only`）。以后要换端口，见 README 第 9 节。
- 开机启动但对外不监听、方案也没要求精简的：snapd、`open-vm-tools` 和 `vgauth`（VMware 工具，这是 KVM 机器）、`inetutils-inetd`、`kdump-tools`、`thermald`、`ModemManager`、`udisks2`、`upower`、`multipathd`、`fwupd`、`sysstat`、`apport`。先不动。
- apt 源在 `/etc/apt/sources.list.d/ubuntu.sources`，指向腾讯云内网镜像；旁边留着一份 `ubuntu.sources.curtin.orig`（指向官方源），apt 不会读它。

## 对脚本草稿的影响

已按这份现状改了（只改草稿，没在服务器上跑）：

1. `wm-snapshot.sh`：加了 `rd`（有 sudo 用 sudo 读）、apt 源、journald 配置、`authorized_keys` 的权限、chrony 配置、`50unattended-upgrades` 的有效行。
2. `wm-harden.sh`：`step_chrony` 五个源配齐就不碰；装包时 `NEEDRESTART_MODE=l`；自动更新生效时提示积压的更新；`sudo` 重新执行时把 `WM_*` 变量一起带上（旧稿里这些变量会被 sudo 清掉，设了也不生效）。
3. `wm-verify.sh`：`time.*` 改查配置文件；列出 `lighthouse` 这类别的可登录账号；本机"密码登录会被拒"的探测改成先把本机主机公钥取到临时文件再连，不再用放宽主机指纹检查的选项。

还等你定：

- `lighthouse` 用户怎么办（留着、不动，还是以后单独处理）。
- 积压的更新什么时候装；要不要在加固前先手动升级一次并重启一次（要你批，动之前先拍快照）。
