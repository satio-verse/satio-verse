# 世界接口契约接进安装流程（2026-11-22）

> 用户 2026-11-22 的原话：**「先做哪步：把接口契约接进装扩展的流程。世界相关的事几乎都卡在这一步。」**
> 这一篇记的就是这一步：改了什么、现在装一个世界包会经过哪几道、怎么自己验、还差什么。

---

## 1. 一句话

以前「世界接口契约」只活在 `wm/agent/plugin_manifest.py` 里 —— 它是个**纯函数校验器**，
谁都没在装的时候调用它（`wm/agent/plugin_host.py` 的模块注释自己都写着「仍然没有接进
`ExtensionRegistry.create()`」）。现在三个来路全部接上了：

| 来路 | 以前 | 现在 |
|---|---|---|
| Creator / 人物自己造 | `extensions.create()` 只看文件名和大小 | 先过契约，世界包连 `wmworld.json` 一起存 |
| 社区市场装包 | 核 sha256 → `create()` | **先给报告**（`inspect`）→ 不合约拒装 → 合约的再真装进插件宿主 |
| 插件页装包 | 走 `plugin_host.install()` | 不变，但进门前已由上面两路卡过一道 |

## 2. 契约长什么样（复习）

可执行版本：`wm/agent/plugin_manifest.py`（纯函数，不执行插件代码）

- `SCHEMA = 2`；`PLUGIN_TIERS = ("text","panel","code","process","builtin")`
- `WORLD_KINDS = ("chat","space","game")`
- `SENSES = ("saw","heard","told","receipt","notice")`
- `URGENCIES = ("piggyback","batch","now","interrupt")`
- 入口：`validate_plugin_manifest(manifest, package_dir=None)`、`policy_issues(manifest, source)`、
  `find_conflicts(manifest, installed)`、`separate_permissions(manifest)`、`has_errors(issues)`

清单文件叫 **`wmworld.json`**（`plugin_host.MANIFEST_NAME`），是一份完整清单：
`{id, name, description, plugin{schema, version, tier, permissions, world{kind, prefix, events, actions, perception, env_prompt}, panel{entry}, ...}}`。
真实样例：`tests/plugin_manifests/plaza-2d.json`。

**没有 `plugin` 块的老包照旧**（`W_NO_PLUGIN_BLOCK` 提示），只是一样会给一份报告。

## 3. 新文件：`wm/agent/install_gate.py`（195 行）

它不新增也不放宽任何规则，只补「装的时候」缺的三件事：

| 函数 | 干什么 |
|---|---|
| `classify(spec)` | 带 `plugin` 块 → `"plugin"`（世界插件）；否则 `"extension"`（老扩展） |
| `inspect(spec, source="third_party", files=None)` | 装**之前**的报告：`{ok, kind, contract{name,schema}, summary, issues, warnings, errors_text}` |
| `gate(spec, ...)` | 不合约直接抛 `ContractError("不符合世界接口契约（N 处）：\n- ...")`，消息是给人看的 |
| `install_plugin_package(spec, plugin_host=None)` | 世界包真装进插件宿主（`~/.worldmodel/plugins/<id>`）；宿主关着就回「已存成草稿」，不假装成功 |

`summary` 里给用户看的是：世界种类（chat/space/game）、前缀、要哪些权限、会往世界里加什么
**动作**和 **事件**、用哪些**感官**、哪些权限要单独授权。

额外加的一条小规则（原校验器不管、但装的时候必须管）：

- `E_ID_MISMATCH`：清单里的 `id` 和包里的 `id` 不一致
- `E_FILE_MISSING`：清单点名要带的文件（`panel.entry` / `world.env_prompt` / `world.spectate.panel` / `world.perception.twin_fixtures[]`）包里没有
- `W_NO_FILES`：包里一个文件都没带（提醒「只能用清单声明的能力」）

## 4. 三处接线

### 4.1 `wm/agent/extensions.py` — Creator / 人物自己造

`ExtensionRegistry.create()` 里加了：

```python
kind = install_gate.classify(spec)
contract = install_gate.gate(spec, files=spec.get("files"))
...
if kind == "plugin":
    clean[install_gate.MANIFEST_NAME] = json.dumps(spec["plugin"], ensure_ascii=False, indent=2)
```

- 世界包的 `wmworld.json` 跟包一起存进版本目录 —— 插件宿主装的时候要的就是这份。
- `ui` 没填时，`plugin.panel.entry` 在包里就当界面（世界面板就是它的预览）。
- 「至少包含 SKILL.md / MCP / HTML 界面之一」这条对世界插件的**放开**（世界包可以只有一个面板 + 动作）。
- `manifest.validation` 里多记 `kind` 与 `contract{name, schema}`，`checks` 多一项 `world_contract`。
- 返回值多 `kind` 和 `contract{ok, world, actions, events}`。

### 4.2 `wm/platform_services.py` — 社区市场

- 抽出 `_fetch(source_id, package_id, version, transport)`（核哈希/编号/版本，装和预览共用，看到的是同一份东西）。
- 新增 `async inspect(...)` → `{id, version, author, report}`（不写盘、不执行）。
- `install()` 改成：`_fetch` → `inspect` → **不合约就 `ValueError` 拒装** → `create` → 世界包再
  `install_gate.install_plugin_package(...)` → 回执带 `kind` / `contract` / `plugin` / `notice`。
- `export()` 把 `wmworld.json` 还原成 `spec["plugin"]`，否则别人装到的世界包会丢清单（这个 bug 是写测试时才发现的）。

### 4.3 `wm/platform_http.py` — 本地 UI

新增 POST 动作 **`community_inspect`**：装之前先看报告（`{source_id, id, version}`）。

## 5. 测试与验收

新文件 `tests/test_install_contract.py` —— **16 passed**，覆盖：

- `classify` 分世界包 / 老扩展；老扩展的报告 `ok` 且不带 `wmworld.json`
- `inspect` 能读出世界需求（`world=space`、`prefix=plaza`、4 个动作、5 个事件、`tier=process`、`127.0.0.1:8801` 权限）
- 缺点名文件 → `E_FILE_MISSING`；`tier` 非法 → `E_ENUM`；`id` 不一致 → `E_ID_MISMATCH`；空 `files` → `E_FILES`
- `gate` 抛 `ContractError`，消息里带契约名和处数
- `create`：世界包连 `wmworld.json` 一起落盘、`has_ui=True`、能 `set_enabled`；老扩展行为不变；没身体的扩展仍报「至少包含」
- 市场：导出 → `inspect` → `install` 全通；篡改掉 `events` 的包被拒且**登记表里一条没留**
- `install_plugin_package` 交给宿主的目录里真有 `wmworld.json` + 三个文件；宿主关着时如实说「WM_PLUGIN_HOST」

回归（同一轮跑）：

```

       tests/test_platform_services.py tests/test_platform_http.py tests/test_platform_package.py \
```

   （在干净环境里是绿的；要修得给测试加隔离，不属于这次改动）。
2. `test_platform_package.py` 原先会挂在部署包白名单上；**已在 `tools/package_platform.py` 的 `FILES` 里补上

## 6. 现在装一个世界包，会走这几道

```
包 JSON（worldmodel_package=1）
  → 市场 _fetch         核 sha256 / 编号 / 版本
  → install_gate.inspect 出报告（不写盘、不执行）
  → 不合约 → ValueError，登记表不动
  → 合约   → extensions.create()
               └ 再 gate 一次（Creator 自己造也走这条路）
               └ wmworld.json 落进版本目录
           → kind == plugin → plugin_host.install()
               └ 清单再校验一遍 + 文件限额 + 先写 .stage-* 再 rename
               └ 授权档从 text 起步，不信任清单自称
           → 回执：{installed, kind, contract, plugin, notice}
```

## 7. 还没做的（说清楚，别当成已做）

- **UI 没接**：`community_inspect` 这个动作有了，但当前工作台/插件页还没有「先看报告再点装」的界面
  （工作台的六区改造按用户的意思排在后面）。

- **回滚**：`plugin_host` 的 uninstall / 版本回退还在扩展那一侧，宿主这边只有整包替换。

## 9. 装前报告接进工作台 + 端到端实测（2026-11-22 08:1x）

### 9.1 UI：市场里多一个「装前报告」

改的是 `desktop\web\workbench-platform.js`（只这一个前端文件，`node --check` 通过，4 处 `https://…example.com` 是原有占位符，不是外链资源）：

- 「发现插件」每个条目从 1 个按钮变 2 个：**装前报告** / 导入扩展。
- 点「装前报告」→ `POST /api/agent/platform {action:'community_inspect'}` → 就地展开一张卡片：
  - 契约名 + schema、版本、`世界插件` 还是 `普通扩展`；
  - 世界摘要：种类（聊天/空间/游戏）、前缀、授权档、本机地址、会不会发通知；
  - 「会加的动作 / 会发的事件 / 它要感知的」三行，超过 12 项写「等共 N 项」；
  - `issues` 前 12 条（`路径：人话（CODE · 错/提醒）`）；
  - 合规才出现「确认导入」，不合规只给「取消」并提示「先改，改完重新发版再刷新索引」。
- 导入成功 / 失败都在原来的 `#platformStatus` 里出中文，不弹 alert。
