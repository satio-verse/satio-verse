# 许可证、商标与「防复刻」说明

> 回答三个问题：为什么选这两个许可证；它们**能**挡什么、**不能**挡什么；想让人不能轻易抄成竞品，真正该做什么。

## 一、我们用的是什么

| 对象 | 许可证 | 说明 |
|---|---|---|
| 代码（wm/、tools/、web/、desktop/、tests/ 等） | **Apache-2.0** | 允许商用、修改、再分发；必须保留版权与许可声明，并声明改了什么 |
| 文档与文字/示意图（docs/ 与 *.md 的文字部分） | **CC BY-NC 4.0** | 允许转载改编，**禁止商业使用**，必须署名 |
| 第三方组件（three.js / three-vrm / Rapier / MediaPipe 等） | 各自许可证 | 见 NOTICE |
| third_party/hast-sec/（若存在） | 非商业学习研究 | 商用前必须移除或另行取得授权 |
| 角色模型、人格、声音、记忆库、美术素材 | **不随仓库分发** | 不在开源范围 |

## 二、它们挡不住的（必须诚实）

Apache-2.0 **不能阻止复刻**：任何人可以下载、修改、闭源再发布（只要求保留声明），
甚至拿它做商业产品而不公开改动。CC BY-NC 只约束文档，挡不住有人照文档重写代码。

## 三、真正能保护你的（按性价比排序）

1. **服务端护城河（最有效）**：客户端开源，但把人格与长期记忆、声音模型、市场与审核、
   更新分发、世界托管、跨设备同步留在你自己的服务器上。抄得走界面，抄不走「她」。
2. **商标 + 品牌**：注册 S.A.T.I.O / Satio Verse 名称与 Logo（至少一个类别）。
   代码可复制，名字与官方分发渠道不能。Apache-2.0 第 6 条已明确不授予商标权。
3. **插件/世界的契约与认证**：世界接入必须过 wmworld.json 契约与装前报告，
   官方目录只收录过 CI 的包；别人 fork 了代码，用户仍只信官方目录。
4. **DCO（提交签名）**：要求 PR 带 Signed-off-by。将来要换更强许可证或做双许可时，
   不必逐个找回贡献者。
5. **想更强：AGPL-3.0 或 FSL/BUSL**
   - AGPL-3.0：改成网络服务对外提供也必须公开修改，挡「白嫖成 SaaS」，仍允许自用与分发。
   - FSL/BUSL：源码可见但禁止做竞争产品，若干年后自动转开源；但不是 OSI 认证的开源证，社区接受度低。
   这是商业取舍而非技术问题，建议等社区有规模再评估。

## 四、现状

- 仓库不含任何 API key、模型权重、人格、记忆库、聊天记录
- 默认只在本机跑（127.0.0.1），没有对外暴露的接口
- 插件权限四档声明式（text / panel / code / process），宿主默认只给 text
- 安装前生成「装前报告」，不合约直接拒装

## 五、商业使用

代码可按 Apache-2.0 直接商用；但请：移除 third_party/hast-sec/（若装了）；
不要用 S.A.T.I.O / Satio Verse 做你的产品名（商标权未授予）；不要把角色形象、声音、人格当你的资产。
