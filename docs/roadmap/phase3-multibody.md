# 阶段三立项: 一脑多态 — 同一个意图在多个本体之间路由, 经验回流

## 1. 目标

WorldModel 基座作为"一脑": 意图解析、置信度、关系记忆、社交后果预测在一处; HAST-SEC 替代品、运动匹配层、
仿真跟踪策略、未来的实体控制器作为"多态". 同一个意图按各本体的可行性和置信度路由, 执行结果回流, 失败和低置信度的经验
进入共享的运动策略、技能库和社交预测器.

## 2. 成功标准

| 指标 | 目标 |
|---|---|
| 一个意图路由到 >= 2 个本体并拿回执行结果 | 端到端打通, 埋点完整 |
| 本体回报的可行性和实际执行结果一致 | >= 90% |
| 回流的失败经验让下一次同类意图的成功率提升 | 可测量的正向提升 |

## 3. 意图协议 v2 (阶段一就开始落地)

现在的意图 (规范化之后):

```json
{"op": "act", "acts": [{"do": "go", "side": null, "to": "sofa", "amp": 1, "spd": 1, "at": 0}],
 "conf": 0.83, "uncertain": false, "escalated": false}
```

`conf`/`uncertain`/`escalated` 已经在阶段一实现 (见 `wm/confidence.py` 和 README). v2 增加两类字段:

1. 本体能力声明 (本体启动时上报, 服务端缓存):

```json
{"body": "vrm-avatar", "skills": {"go": {"feasible": true}, "sit": {"feasible": true, "targets": ["sofa"]},
 "pick": {"feasible": true, "max_mass_kg": 0.5}, "leg": {"feasible": false, "reason": "无动捕技能"}}}
```

2. 执行结果回报 (每个动作结束时上报):

```json
{"type": "act_result", "turn": 12, "index": 0, "body": "vrm-avatar", "status": "done|failed|skipped",
 "reason": "走不到那里", "t_start": 1234.5, "t_event": 1236.1, "t_end": 1237.0, "conf_exec": 0.92}
```

服务端用能力声明过滤 LLM 的动作 (不可行的不下发, 改成口头回应), 用执行结果更新置信度校准和技能库.
陪伴场的前端已经有"走不到那里""手里没有东西"这类失败提示 (`onNotice`), 是 `act_result.failed` 的雏形.

## 4. 范围与里程碑

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| M0 协议 | 意图协议 v2 落到 JSON Schema 和 WebSocket; VRM 前端上报能力和执行结果 | 阶段一 |
| M1 路由 | 服务端按能力 + 置信度把意图路由到一个或多个本体; 同时驱动 VRM 和仿真本体 | 阶段二 M2 |
| M2 回流 | 执行结果进入: 置信度校准 (按本体)、技能可行性表、社交后果预测器 | 阶段一的社交数据 |
| M3 共享技能库 | 不同本体执行同一技能的经验汇总, 一个本体学会的技能 (参考运动 + 成功率) 其他本体可直接尝试 | 阶段二 M3 |
| M4 多智能体 (可选) | 多个本体协作完成一个任务 (分工、交接) | M1-M3 |

## 5. 参考方向 (用户提供的材料, 均待核实)

多机器人闭环协作与集体长期记忆 (SEFM)、已部署机器人共享执行经验的集体经验学习 (CEL)、一个大脑指挥多种形态机器人
("一脑多态")、自进化的具身导航智能体 (DR-Agent). 这些只作为思路参考, 立项时不依赖其中任何一个的代码.

## 6. 风险

| 风险 | 应对 |
|---|---|
| 各本体的时延差异大, 同一意图的表现不同步 | 协议里带时间戳, 路由层按最慢本体对齐或允许异步 |
| 回流数据质量 (规则粗标的社交标签、仿真失败原因不明) | 先人工抽检, 标注可修正 (Obsidian/JSONL 都是人可读的) |
| 协议过早固化 | v2 字段全部可选, 带版本号, 向后兼容 |
