## 0. 结论先说

- **能做，而且我们已经有一半。** 宿主的工具中枢（MCP 客户端、自动 / 每次确认 / 禁用三档权限、操控电脑五档和守门、skill、内置工具、调用记录、内容包）、服务端的云端模型多轮工具调用（`wm/cloud.py`）、QQ 渠道和"15 秒没人点就上 QQ 审批"、她的工作台（借 dsh 写代码、门禁、备份退回），这些都是 DSH 那一套里的零件。
- **缺的是三块：**
  1. **干活的智能体循环**：读写改文件、跑命令、搜索，带会话、工作区、计划 / 目标模式、上下文压缩。现在服务端的工具调用只为聊天服务，写代码靠外面的 dsh。
  2. **像 DSH 的工作台窗口**：工作区和会话列表、模式、权限、模型选择、`/` 指令、侧边卡片（文件、改动、终端、任务、浏览器）、费用栏。
  3. **生态**：插件市场（扩展中心 E2）、技能中心和技能市场、IM 扫码接入、余额和峰谷。
- **建议：自己写核心循环，界面学 DSH，不 fork dsh、不兼容 dsh 的插件。**
  - 核心循环用 Python 放在服务端（`wm/agent/`），和她的陪伴大脑共用模型配置、记忆、审批卡片、看守进程。
  - dsh 先留着当工作台的"手"，等我们的循环在同一套任务上追平它，再把工作台换过来（第 6 节 H6）。这和 2026-10-25 定的"dsh 不当她的大脑"不冲突：大脑一直是我们自己的，这次是把"手"也换成自己的。
- **一处不学：DSH 的"完全权限"不拦任何东西。** 我们所有档位都保留守门名单、高风险每次问、15 秒上 QQ 审批。安全边界不降。
- 余额峰谷（第 3 节）最小、最快有用，建议先做；IM 扫码（第 4 节）的微信是我们现在没有的通道，第二个做。

## 3. 余额、峰谷、订阅（回答第一个问题）

**余额挂件是怎么做的**（据它的 README）：
- 余额：每 60 秒调一次 DeepSeek 的 `GET https://api.deepseek.com/user/balance`，点一下手动刷新；网络抖一下就先显示上一次的。
- 今天花了多少：不用额外接口。余额往下掉就算花掉的，往上涨（充值、赠金）单独记；每一轮的花费从 DSH 本地的会话记录里按未命中、命中、输出、推理 token 算。
- 峰谷：北京时间工作日 9:00–12:00、14:00–18:00 是高峰，其余是低谷；2026-08-23 起周末全天低谷；低谷半价。价格表（元 / 百万 token，低谷 / 高峰）：flash 命中 0.02 / 0.04、未命中 1 / 2、输出 4 / 8；v4-pro 命中 0.15 / 0.30、未命中 4.5 / 9、输出 13.5 / 27。**这些数是二手的，用之前要对 DeepSeek 官方价格页核实。**（我们工作台的 `PRICE` 现在是 2 / 0.04 / 8，正好是 flash 的高峰价。）
- 其他订阅：34 家模板。OpenRouter、Kimi 这类有余额接口的按 JSON 路径读出来；没有的只验 key、按 token 估。key 只发给模板里写死的地址，自定义地址要单独点同意。

**我们怎么做**：
- 服务端每一轮已经拿到用量了（`cloud.py` 的 `_usage`，含缓存命中和推理 token），只是没记账。加一个账本：每轮一行（时间、谁花的：桌宠 / QQ / 工作台 / dsh、提供方、模型、未命中 / 命中 / 输出 token、高峰还是低谷、花了多少），按天汇总。
- 余额：DeepSeek 用 `/user/balance`；Kimi 等有余额接口的读接口，其余按 token 估。余额请求在服务端发：key 本来就随人设预设交给服务端，只放在 `cloud.py` 的对象里、不进日志；面板照旧拿不到明文。key 只发给模板里写死的余额地址。
- 价格表和峰谷时段放配置，不写死（价格会变）。
- 显示：工作台左下角、设置的"账号与余额"页、桌宠侧菜单悬停；余额低于阈值时她在对话栏提一句。
- **让她自己用峰谷**：她自己发起的、不急的花钱事（工作台研究、自己写 MCP、看视频写感想）高峰时排到低谷做，省一半。这是给她一个"现在贵不贵"的感知，怎么安排让她自己定（照"别替她解决"那条）。

## 4. 为什么 dsh-im 扫个码就能接（回答第二个问题）

不是 dsh-im 有什么特别的本事，是 **2026 年这些平台自己开了"给 AI 代理接入"的官方通道**（OpenClaw 那波热潮带起来的）。扫码代替了"注册开发者、建应用、抄密钥、配回调地址"这几步；收消息都走长连接或长轮询，电脑不用公网 IP。

| 平台 | 扫码其实是在做什么 | 收消息 | 限制 |
|---|---|---|---|
| 微信 | 腾讯 2026-03-22 出的 ClawBot 插件 + iLink 后端（`ilinkai.weixin.qq.com`）。扫码 = 用你的微信授权一个 ClawBot 联系人绑到这个程序，程序拿到令牌 | 长轮询（资料里的接口名：`get_bot_qrcode`、`get_qrcode_status`、`getupdates`） | ClawBot 是你通讯录里一个单独的联系人，只能和你一对一，进不了群 |
| QQ | QQ 开放平台的官方机器人。扫码 = 用手机 QQ 一键建一个官方机器人（不用去开发者后台），程序拿到 AppID / AppSecret | WebSocket 长连接 | 带"机器人"标（截图里"大肥鱼"后面那个小图标）；群里只有 @ 它才收到、才回；没有 QQ 空间；传文件有每日额度 |
| 飞书 | 扫码建机器人应用 | 长连接 | 群里要被 @；读图片文件要另开权限 |
| 钉钉 | 扫码建机器人 | Stream 长连接 | 流式回复用 AI 卡片 |
| 企业微信 | 在企业微信里扫码建智能机器人 | 官方 WebSocket | 自建应用那种还是要手动配回调 |

**对比我们现在的 QQ**：她用自己的 QQ 小号，经你电脑上的 SnowLuma（挂着一个 QQ 客户端，OneBot 协议）。好处是她就是一个普通群友：看得到群里所有的话、自己插话、发说说、看 B 站分享；坏处是要你装 SnowLuma、非官方协议有封号风险、门槛高。

**建议两条都要**：
- 官方扫码通道做"主人随时找她、远程派活"。微信是我们现在完全没有的。消息照现有信任分档：只有核对过的主人能派活，审批照样问到这条通道上。
- SnowLuma 继续做"像真人的群友"。官方 QQ 机器人只能被 @，当不了群友。
- 能自己做：dsh-im 是 MIT，可以参考它怎么写。微信那条服务端用 Python 写一个通道：取二维码 → 面板显示 → 轮询扫码状态 → 令牌交给宿主 DPAPI 加密存 → 长轮询收发。QQ 官方的"扫码建机器人"接口没有公开文档（dsh-im 的 README 也没写），要先读它的源码确认；读源码不用装，但下载仓库前先问你。

## 5. 核心循环怎么做

### 5.1 放哪

服务端 Python，新包 `wm/agent/`：
- 模型配置、记忆、QQ 审批（`_ask_card`）、看守进程都在服务端，放一起最省事；
- 工具在服务端执行（文件、终端、搜索），权限判断复用现有的确认卡片和 15 秒上 QQ；
- 宿主的守门名单（`guard.cpp` 的命令黑名单、`kProtectedPaths`）抽成一份规则文件，C++ 和 Python 都读，不写两份；
- 操控电脑照旧走宿主和 Windows-MCP。

### 5.2 一个会话里有什么

- 工作区 = 一个文件夹（建议别放 C 盘，和 DSH 那篇的建议一样）；会话存在 `%APPDATA%\WorldModel\agent\sessions\<编号>.jsonl`，能导出。
- 模型和工具来回多步，每一步记轨迹（用了什么工具、参数摘要、结果字数、耗时、花了多少），"轨迹"标签页就是它。
- **上下文压缩**：学 billion-context。DeepSeek 的缓存按前缀命中，压缩只动尾部、整块替换，不然每压一次缓存全失效、反而更贵。旧的工具输出先折成摘要，再不够才压对话。
- **Agent 预设（模式）**：标准（文件 + 终端 + 搜索）；计划（先列计划，你点了才做，对应 `/plan`）；目标（长跑，有花费和时间上限，对应 `/goal`）；极简（只有终端，测基础能力）；创造（写 skill、MCP，就是现在 `selfmcp` 那条，按第三方扩展走确认）。

### 5.3 权限四档

| DSH | 我们 | 守门 |
|---|---|---|
| 仅可查看 | 只读工具自动，写和命令不给 | 保留 |
| 工作区内修改 | 工作区里读写自动，工作区外只读，命令每次确认 | 保留 |
| 完全权限 | 工作区外也能写、能跑命令，**高风险每次问** | 保留 |
| Auto review（实验） | 另一个便宜模型先看，低风险的自己放行，看不准的问你 | 保留；先只在"工作区内修改"上试 |

QQ 上远程派的活默认最多到"工作区内修改"（`self-evolution.md` 里提过的口子，用户当时说先不动；做这块时再问一次）。Windows 上第一版不做系统级沙箱，靠路径检查、守门和审批；以后再看低完整性进程或 AppContainer。

### 5.4 和她的关系

同一个她，两条路：陪伴对话（`pipeline`，要快、要出声）和干活（`wm/agent`，慢、多步）。陪伴里认出"这是活儿"就开一个工作台会话，桌宠上她坐到电脑前，做完回来跟你说。QQ 上派的活（现在的 `computer_task`）也进工作台会话，你在工作台窗口里看得到她在 QQ 那边接了什么活、做到哪了。

### 5.5 怎么知道做得好不好

"高命中率"DSH 没公开过数字，我们自己量：固定一套任务（比如 20 个小的找文件、改代码、跑测试、整理资料），我们的循环和 dsh 各跑一遍，比做成了几个、一次选对工具的比例、你要纠正几次、花了多少钱、用了多久。跑真模型要花钱，每次先估价、你点了再跑；结果记进实验记录。

### 6.1 H0 做了什么 (2026-10-26)

用户定了先做 H0, 中途补了"还有命中率、缓存、kv cache、未命中率、token 消耗量等等, ai 也可以随时读取到这些内容, 相当于之前在桌宠中做的各种零食、饮料、用餐、投喂等资源".

- **服务端账本** `wm/ledger.py`: 每次云端请求记一行 (谁花的、模型、命中 / 没命中 / 输出 / 思考 token、高峰还是空闲、花了多少、缓存省了多少), 本机模型记 KV cache 复用; 按天写在 `<trace.log_dir>/billing/`. 价格和峰谷在配置 `billing` 段 (2026-10-26 对过 DeepSeek 官方价格页). 工作台的 dsh 每一步也记进来.
- **余额**: 服务端去查 DeepSeek `/user/balance` (正在用的 DeepSeek 模型的 key, 或环境变量), key 不进账本、不经过面板; 每天记第一次和最近一次的余额, 算出"今天少了多少"和充值.
- **她看得到**: 云端那一轮多一行 `[钱包]` (余额、今天花了多少、缓存命中、现在是不是高峰、多久换档); QQ 只在主人档带. 怎么用由她自己定. 小屋心情牌里也有一行钱包.
- **面板"账号与余额"页**: 余额大字、峰谷 24 小时时间条和价格表、今天和这个月 (花费、token、命中率、没命中率、谁花的、本机 KV cache)、14 天柱状图 (悬停、表格)、最近 30 条. 深浅色都看过.
- **测试**: `tests/test_ledger.py` 10 条; 全套 pytest; `paneltest` 29 项 (加了假账本和假余额接口). 修了 `test_proactive_owner` 原来就有的时序竞争.
- **没做的**: 别家 (Kimi、OpenRouter) 的余额; 自定义订阅模板; 余额低时她主动提醒你 (现在她看得到, 说不说由她); 2027 年的法定节假日 (国务院公布后补进 `billing.peak.deepseek.holidays`).

## 9. 只下载一个桌宠就能用 (2026-10-26 晚, 用户问的; 方案, 待定)

现在要分开起好几样: 桌宠 (`wmpet.exe`)、服务端 (`python -m wm`, 看守 `tools/serve.py`)、本机模型 (`llama-server`, 8784)、嵌入 (8786)、语音合成 (GPT-SoVITS, 9880), QQ 还要 SnowLuma. DSH Desktop 的做法是"应用自动启动和管理本地服务, 无需安装 Node.js 或执行命令". 我们照这个分四步:

## 7. 不学的、风险

- 不学"完全权限什么都不拦"。
