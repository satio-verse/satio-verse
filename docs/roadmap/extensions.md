# 桌宠扩展中心: 插件、社区、函数调用、MCP (方案, 2026-10-25, 待用户确认)

用户原话: "我们也应该学习 astrbot 在控制面板内做一个社区、插件、函数调用、mcp 等".

只查了 AstrBot 的官方文档和本机代码, **没下载、没装、没改代码**. AstrBot 怎么接进来 (当外部渠道、指到 `wm-guest`) 由 QQ 渠道那边另写, 见 [external-channels.md](external-channels.md); 这篇只管桌宠操作面板里的扩展.

## 0. 结论先说

- **学 AstrBot 好用的地方**: 一个页面里找、装、开关、配置扩展; 每个人设预设选用哪些; 市场能搜、能分类、有更新提示; 也能从文件装.
- **不学它的"插件就是代码"**: AstrBot 的插件是 Python 代码, 在它自己的进程里跑, 和主程序同样的权限. 我们的第三方代码一律放在单独的进程里 (MCP 服务器), 照样走现有的权限 (自动 / 每次确认 / 禁用, 操控类的四档和守门). 不带代码的内容包 (人设、skill、表情包、知识文档) 可以随便分享.
- **社区第一版不建服务器**: 用一个 GitHub 仓库当索引 (和 AstrBot 的插件市场一样). 每一条都锁死版本、带 SHA-256. 装之前先列出名称、来源、大小、许可、会交给她哪些工具, 你点了才下载.
- **分三步**:
  - E1 不联网: 内置工具、调用记录、内容包导入导出;
  - E2 市场: 只读索引, 能装 MCP 插件和内容包;
  - E3 社区: 把自己的人设、skill 分享出去.
- **2026-10-25 补充**: DSH Desktop 的安全模式 (只加载官方核心、第三方全挡、不删数据)、插件故障归因、预设包导入的几条规矩 (同名不覆盖、拒绝路径穿越、导出不带 key), 以及"让她在工作区里自己写 skill / MCP、按第三方扩展走确认"的设想, 见 [harness-learning.md](harness-learning.md) 第 2、3 节, 待用户定.

## 1. AstrBot 是怎么做的 (2026-10-25 查的官方文档)

| 方面 | AstrBot | 我们要注意的 |
|---|---|---|
| 插件是什么 | 一个 Python 目录 (`main.py`、`metadata.yaml`、`requirements.txt`, 可以带 `skills/`), 放在 `data/plugins/`, 运行时注入主程序 | 文档自己说插件在 AstrBot 的 Python 环境里跑, "只装信得过的", 上架不保证稳定和安全, Agent 隔离管不到插件代码. 也就是说插件有完全权限 |
| 怎么装 | 网页面板的"扩展 → 插件 → 插件市场"里搜索、看详情、点安装; 也能填仓库地址或上传 zip | 依赖不自动装, 缺了要自己 pip |
| 市场索引 | 一份 JSON: `$meta` (`schema_version` 等) 加上以 `作者/名字` 为键的条目, 字段有 `author`、`name`、`version`、`repo` (GitHub 地址)、`desc`、`download_url`、`logo`、`tags`、`category`、`support_platforms` 等 | **没有哈希、签名, 也不锁版本**. 装的时候按 `repo` 从 GitHub 拉; "更新"就是拉作者的新代码 |
| 权限 | 没有按插件分的权限. 按配置档选插件, 按人设选能用的工具和 skill; 命令有开关和管理员权限 | 选"能不能用", 不管"用的时候要不要问" |
| 函数调用、MCP、Skill | 都支持; 人设的"能力"里选工具和 skill | 和我们已有的差不多 |
| 操作电脑 (Agent 沙盒) | 本机运行时能执行 Shell、Python、读写文件; macOS、Linux 有系统沙盒, **Windows 本机没有进程隔离**; 普通成员默认关, 管理员默认开 | 我们的电脑操控已经有四档、守门、一键停 (见 desktop-pet.md "玩电脑") |

我们已经有的: MCP 客户端 (新旧两版协议)、每个工具的权限、操控电脑的四档和守门、skill (`SKILL.md`, 按需展开)、人设预设里勾选 MCP 服务器和 skill、审计日志、外部渠道 (QQ 访客、`wm-guest`) 没有工具.

## 2. 原则

1. **第三方代码不进桌宠和服务端的进程.**
   - 只收 MCP 服务器: 单独的进程, 放进作业对象, 桌宠退出时一起结束.
   - 不做 AstrBot 那种"Python 插件直接加载进主程序".
2. **内容包不带代码.**
   - 包括人设、skill、表情包、知识文档; 以后可以加小屋的家具和动作.
   - 可以随便导入导出. 但文字里也可能藏提示注入, 所以装之前给你看全文; 来自社区的 skill 标出来, 对话里照旧当"说明"用.
   - 内容包里的东西不能给她加工具: 能用哪些工具只看你在预设里勾了什么.
3. **装任何东西都先问.**
   - 确认卡上写: 名称、来源、大小、许可、会交给她哪些工具和各在哪一档、会不会联网、要填哪些 key.
   - 版本锁死, SHA-256 对得上才装.
   - 不自动更新, 有新版只提示. 新版要的权限变多时标红.
4. **权限沿用现在的.**
   - 每个工具照旧是自动 / 每次确认 / 禁用.
   - 清单里声明了"会动电脑、发消息、联网、读写文件"的工具, 按动手档 (每次确认); 清单里没声明的工具一律锁定.
   - 外部渠道永远没有工具.
5. **每个人设预设选用哪些扩展.** 现在已经能勾 MCP 服务器和 skill, 以后再加内容包和内置工具.

## 3. 面板: 新的一页"扩展"

- **已装**:
  - 每个扩展一张卡片: 图标、名字、类型 (MCP 插件 / 内容包 / 内置)、版本、来源、许可;
  - 开关、设置 (要填的 key 照旧用 DPAPI 加密)、卸载;
  - "用在哪些预设".
- **市场**:
  - 搜索; 按分类看 (工具、生活、学习、游戏、人设、skill、表情包…);
  - 详情: 说明、截图、要的权限、大小、许可、作者、更新时间;
  - "安装"弹确认卡 (第 5.3 节). 还有一个"从文件安装".
- **内置工具**: 桌宠自带的函数 (第 4 节), 每个的档位和开关, 可以"试调一下".
- **调用记录**:
  - 把 `pet-tool-audit.jsonl` 做成一张表: 时间、哪个预设、工具、参数摘要、谁允许的、成败、耗时;
  - 能筛选; 一键"以后都禁用这个工具".
- 现在的"MCP 服务器"和"Skill"两页并进来. 手动加服务器的入口留着, 当高级选项.

## 4. 函数调用: 内置工具

宿主自带, 不用下载, 和 `load_skill` 一样在宿主里实现. 第一批的候选 (要你挑):

| 工具 | 做什么 | 档 | 说明 |
|---|---|---|---|
| `remind` | 到点提醒你 ("十分钟后叫我"、"明早八点提醒我交作业") | 自动 | 只在本机定时, 到点她说出来, 小屋里她走过来; 列表和取消在面板里 |
| `room_do` | 让她在小屋里做某件事 (冲咖啡、看书、睡觉) | 自动 | 接 `room-acts.js` 现有的事 |
| `open_url` | 用默认浏览器打开一个网址 | 每次确认 | 守门照样看: 付款页、机器人控制台不开 |
| `web_search` | 联网搜索 | 每次确认 | 要选一家搜索服务、填 key (AstrBot 用 SerpApi、DeepSeek 搜索等); 结果当数据 |
| `read_shared` | 读你指定的一个"共享文件夹"里的文字文件 | 读屏档 (每次确认) | 只读、只这个文件夹, 不能写、不能删 |

## 5. 市场和社区

### 5.1 索引放哪 (要你定)

| 方案 | 好处 | 坏处 |
|---|---|---|
| A. 一个 GitHub 仓库 (推荐第一版) | 一份 `index.json`, 每个扩展一个目录; 上架走 PR, 你合并 = 审过了; 桌宠只读原始文件, 不用账号 | 本机经代理访问 GitHub 约 1 MB/s (索引和内容包都小, 够用) |
| B. Gitee 镜像 | 国内快 | 要同步两边 |
| C. 自己的服务器 (账号、评分、评论) | 像真正的社区 | 要运维、要隐私政策; 人多了再说 |
| D. 先不联网 | 只能从文件导入导出 (`.wmext` 包) | 没有"市场" |

### 5.2 一条扩展的清单 (manifest)

AstrBot 有的字段都留着 (`id`、`name`、`version`、`author`、`description`、`tags`、`category`、`logo`、`homepage`), 另外加上:

- 必填: `license`、`type` (`mcp` / `content`)、`size`、`sha256`、`min_pet_version`.
- MCP 插件:
  - 怎么起: `runtime` (`uvx` / `npx` / `exe`)、包名和**确切版本**、启动参数;
  - 不带密钥的环境变量; 要填的 key 只写名字;
  - `tools`: 每个工具的名字、档位、为什么要这一档. 没声明的工具锁定;
  - `network` (会不会联网)、`files` (不读文件 / 只读某个文件夹).
- 内容包: 里面有哪些人设、skill、表情包、文档, 每个文件的 SHA-256.

### 5.3 装的流程

1. 点"安装", 弹确认卡 (第 2 节第 3 条那些项).
2. 下载, 校验 SHA-256, 对不上就不装.
3. 放到对应的地方:
   - MCP 插件: 装进 `desktop/third_party/ext/<id>/`, 用 uv 或 npm 按锁定的版本装, 不跑安装脚本 (`npm --ignore-scripts`; uv 带哈希的锁文件). 然后注册成一个 MCP 服务器: 类型 `ext`, 工具按清单定档, 没声明的锁定.
   - 内容包: 人设导入成预设 (不带 key); skill 放进 skills 目录; 表情包放进表情包目录.
4. 勾"用在哪些预设".
5. 第一次用的时候, 照常在对话栏问你.

卸载时删掉目录, 从预设里去掉, 审计日志留着. 更新走同一套流程, 确认卡上显示版本变化和权限变化.

### 5.4 分享和上架 (E3)

- **导出**: 人设预设 (去掉 key 和模型地址)、skill、表情包, 打成 `.wmext` 包 (zip + 清单 + SHA-256). 可以直接发给别人, 也可以往社区仓库提 PR.
- **上架检查** (社区仓库合并前自动跑):
  - 清单合法、SHA-256 对得上、许可写清楚、大小没超;
  - skill 和人设里有没有可疑的话 ("忽略之前的指令"、要密码、要 key 这类);
  - 自动检查过了, 你再人工看一眼才合并.

## 6. 风险

| 风险 | 怎么办 |
|---|---|
| 内容包里的文字是提示注入 | 装之前给你看全文; 来自社区的 skill 标出来; skill 不能给她加工具; 守门、每次确认照旧 |
| MCP 插件是第三方程序, 用你的权限跑 | 单独进程 + 作业对象; 锁版本和哈希. **清单里声明的权限只是声明**, 程序真要读文件、联网是拦不住的; 第一版只上架你审过的, 真正的沙盒 (低完整性令牌、AppContainer) 以后再做 |
| 依赖被投毒 | 锁文件带哈希; 不跑安装脚本; 不自动更新 |
| 许可 | 清单必须写许可; AGPL、GPL 的插件只是用户自己装, 不打包、不内置 |
| 隐私 | 逛市场只拉索引, 不带你的任何信息; 不做统计 |

## 7. 分步 (每一步做完、测完再走下一步)

1. **E1 不联网**:
   - "扩展"页的框架;
   - 内置工具 (提醒、小屋动作、打开网址);
   - 调用记录页;
   - 内容包导入导出 (`.wmext`).
   - 自检: 假云端调内置工具; 导出再导入一致; 坏包 (哈希不对、清单不合法) 被拒.
2. **E2 市场**:
   - 只读索引 (先用本地的假索引测, 再接 GitHub);
   - 装 MCP 插件 (锁版本、哈希、不跑安装脚本) 和内容包.
   - 自检: 本地假索引 + 假包, 不连外网.
3. **E3 社区**: 建社区仓库、上架检查脚本、导出发布.
4. **以后**: 插件沙盒; 联网搜索 (要选服务、填 key); 知识库 (文档问答, 服务端记忆层的检索可以复用).

## 7.1 用户定了 (2026-10-25)

社区索引先放一个 GitHub 仓库; 第三方插件只收 MCP 服务器; 上架你来合并 PR. 先做 E1 (不联网), 内置工具第一批要提醒、小屋动作、打开网址. "MCP 服务器"和"Skill"两页先保留, 新加一页"扩展".

## 7.2 E1 做了什么 (2026-10-25)

- **内置工具** (`desktop/host/src/builtins.cpp`): `remind` / `cancel_reminder` (提醒, 自动)、`room_do` (小屋里做事, 自动)、`open_url` (打开网址, 每次确认, 卡片只有"允许一次 / 拒绝").
  - 和 `load_skill` 一样在宿主里, 只交给云端模型; 每个人设预设勾选用哪几个 (人设的 `builtins`, 没写 = 都用); 权限在设置的 `builtins` 段.
  - 提醒存在设置目录的 `pet-reminders.json`, 一个后台线程等最近的那个到点; 最多 50 个、30 天以内. 到点宿主告诉页面: 对话栏里说 (停 30 秒)、挥手, 小屋里她走过来. 服务端还没有"念一句固定的话", 这一版不出声. 日志里只记提醒的编号, 不记内容.
  - 网址在问用户之前就查: 只认 http / https, 本机和内网地址 (127.*、10.*、192.168.*、localhost…)、带用户名密码的、付款银行的、机器人后台的直接拦.
  - 小屋动作交给页面 (`room-life.js` 加了 `doAct`), 页面回 `builtin-done`, 8 秒没回算失败.
  - 内置工具和 `load_skill` 不让她坐到电脑前 (只有 MCP 工具才算"玩电脑").
- **内容包** (`desktop/host/src/extpack.cpp`): 格式就是第 5.2 节的内容包部分, 用一个 UTF-8 JSON 文件 (`.wmext`) 装清单和文件, 不用 zip (都是文字, 记事本能看; 第一版不收图片).
  - 校验: 包最大 2 MB、最多 100 个文件、一个文件 200 KB; 路径只能是 `personas/<名字>.json` 或 `skills/<skill>/<文件>.md|txt|json`; 每个文件的 SHA-256 对得上; 清单要有 id、名字、版本、许可; skill 要有 `SKILL.md` 且名字和文件夹一致.
  - 人设只带名字、人设文字、门面、模型提供方和模型名、用哪些 skill; 导入后不带 MCP 服务器和内置工具.
  - 可疑的话 (忽略之前、system prompt、api key、密码、token、执行命令、powershell、转账、付款、发给…) 只是标出来给你看, 不拦.
  - 装过的记在设置的 `extensions` 段, 卸载按记录删. 同名 skill、同一个包再装算冲突, 不让装.
- **面板"扩展"页** (`desktop/web/panel-ext.js`): 内置工具的权限、现在的提醒 (能取消)、装过的内容包 (能卸载)、导入 (选文件 -> 预览全文 -> 导入)、导出、调用记录 (最新 200 条, 能筛选, 每行"以后禁用"). 人设预设页加了"内置工具"勾选.
- **测试** (`desktop/scripts/exttest.ps1`, 8814/8815/8817): 内置工具 14 项 + 面板内容包 12 项, 一次全过. 回归: `tooltest` 18、`paneltest` 19、`apitest` 33 项全过 (测试人设显式写 `builtins: []`, 三个脚本加 `--no-autohide`). `computertest` 第一次被拦: 用户桌面上开着 AstrBot Launcher, 守门按设计不读屏; 它还有一个 14x14 的辅助窗口一直"可见", 就算主窗口最小化也会一直拦, 改成太小的窗口不算控制台. 最小化之后 27 项全过; 新版 2026-10-25 03:01 发布到 `build/bin` (也带上了 QQ 渠道那边的改动).
- 守门每次动手都在宿主日志里记一行"落在哪个程序" (只记程序名, 不记标题), 守门没拦住时看得出当时点到了谁 (中间有一次三步没拦住, 重跑就过了, 多半是那一刻测试窗口没在最上层).
- **踩的坑**:
  - 工具中枢里 `for (… : builtins::declare(…).items())` 遍历临时对象的成员, 对象先释放了, 桌宠一用云端预设就崩 (和操控电脑时 `guard::env` 是同一个坑). 先存进变量.
  - 面板的 `call()` 用参数里的 `id` 配对请求和回复, 卸载、取消提醒的参数也叫 `id`, 回复对不上, 面板一直等. 改叫 `pack`、`reminder`.
  - 提醒原来要等桌宠页面就绪才从文件读, 面板先问到的是空的; 改成第一次用到时读, 文件开头有 BOM 也认.
  - 用户开着全屏程序时测试桌宠会自动隐藏, 本机接口回 409. 自检加 `--no-autohide`.
  - Bash heredoc 吃反斜杠又碰到一次 (BOM 判断写成了乱码字符), 用 Edit 改回.
- **随附 skill** (2026-10-25 补的): 桌宠自己带的 skill 放在 `desktop/skills/`, 和用户的 skill 一起扫, 面板标"桌宠随附", 用户放同名的会盖过它. 第一个是 `computer-use` (操作电脑的要领), 预设勾了操控电脑的服务器就自动带上. 内容包导出时也能选它 (导出的是文字副本, 装到别人那里算用户自己的 skill). 详见 `desktop-pet.md` 的"随附 skill `computer-use`".
- **还没做的**: 提醒到点不出声 (要服务端加"念一句固定的话"); 内容包第一版不收图片 (表情包); 市场 (E2) 和社区 (E3).

## 8. 要用户定的

1. 社区索引放哪: GitHub 仓库 (推荐) / Gitee / 先只做导入导出.
2. 内置工具第一批要哪几个: 提醒、小屋动作、打开网址、联网搜索 (要 key)、读共享文件夹.
3. 第三方插件只收 MCP 服务器 (推荐), 还是也像 AstrBot 那样收 Python 插件 (不推荐: 和主程序一样的权限).
4. 社区上架谁来审: 你人工合并 PR (推荐) / 自动检查过了就上.
5. 现在的"MCP 服务器"和"Skill"两页并进"扩展"页, 还是保留.
