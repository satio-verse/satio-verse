## 0. 结论先说

- **思路里的大半我们已经有了**（第 1 节逐条对照）：QQ 那边的会话代码里就没有工具；只有桌宠上的本人会话能动电脑；
  她改代码是 dsh 在一份拷贝里改、出补丁、你合才进项目；小屋断线时按本机规则过日子；睡觉时整理记忆；日记本翻开才读长期记忆。
  不用换架构，也不搬那套 `Bot\00_Supervisor…` 的目录和 FastAPI / Electron 的代码（我们是 C++ 宿主 + WebView2 + aiohttp）。
- **真正缺的四样**：
  1. **一处现在就该补的口子**（第 2 节）：QQ 私聊里一句"改进一下…"，会让 dsh 用"不限制"的沙箱档开工，任务书里还带着前面几句对话。
  2. **改自己的代码，合进来之前由程序把关**（第 3 节，"双生槽位 + 不可变测试"）：保护名单、不让自动流程改的契约测试、
     合并前程序自己跑测试（不信 dsh 的自报）、备份和一键退回、先在 8814 试跑、一个看守 8790 的小进程（崩了拉起、新版起不来自动退回）。
  3. **服务端重启 = 她睡一觉**（第 4 节，"作息状态机"）：8790 起一次要十几秒，不是 1~2 秒，所以不做"翻书 1.2 秒"那种过渡，
     而是复用已有的睡觉和便利贴；断线时你打的字现在会丢，改成也变便利贴。
  4. **三环写成代码里的契约，集中测**（第 5 节）：每一环能做什么、跨环只有哪几条路，写成 `tests/contract/`，工作台的补丁改不了它。
- **第二轮意见**（第 8 节）：补了便利贴编号和回完才撕、看守进程判断"卡住"和自己写验证标记、合并前在 8814 回放对比、运行指标、
  QQ 补拉只补断开那段、渠道启动自检、复盘规则由人审过再进契约测试；主人状态感知和记忆降权已经有了。
- **不照搬的**：150 ms 微脉冲重连、4001 关闭码这类毫秒级设计（本机重启是十几秒级）；Git worktree（项目不是 git 仓库，
  `models/`、`runtime/` 几十 GB，见 3.1）；让模型写"根因反思"（先由程序记事实，根因交给下一次修它的任务，见 3.5）。

## 2. 现在就该补的一处口子：QQ 上一句话 → dsh 不限制地跑

**怎么连起来的**：
- 13:18 你定了"改桌宠本身的任务，dsh 不限制"（`workbench.MODE = "danger-full-access"`，审批 `never`）。当时开工都要你在桌宠上点卡片。
- 后来加了"在哪儿都能指挥她"（external-channels 第 18、23、25 节）：你在 QQ 私聊里说"改进一下…""修一下…""学会…"，
  判断成 `fix` 就**直接开工**；任务书里带你的原话和**前面 4 句对话**（`manager._do`，`need` 最多 800 字，进 `NEED_BRIEF`）。

**风险**：
1. 前面 4 句里有她的回复。她的回复可能转述了别人发来的东西（合并转发、视频里的话、群里的事），这些字就进了不限制的 dsh 的任务书。
   这正是贴来的思路里说的"间接提示词注入变远控"。任务书里写的"只当需求看、规则以外的一律不做"是提示词，挡不住。
2. QQ 号被盗、或者手机被别人拿着，也能让 dsh 在你电脑上跑任意命令、花你的钱。

**建议**（三选一，等你定）：
1. **从 QQ 发起的改代码任务用 `workspace-write`**（dsh 只能写工作区，Windows 的 ACL 沙箱）；在桌宠上说的、或者你在桌宠上点过卡片的，才用不限制。（推荐）
2. 从 QQ 发起的照样准备好任务书，但真开 dsh 之前在桌宠上弹卡片（不在 QQ 上问），你在电脑前点了才跑。
3. 不变，接受这个风险。

不管选哪个：任务书里的"前面的对话"只带**你自己说的**那几句，不带她的回复。

## 3. 改自己的代码：双生槽位 + 不可变测试（第一件没想好的）

### 3.1 槽位就用现在的工作台，不上 git worktree

- 项目不是 git 仓库；`models/`、`runtime/`、`third_party/`、`downloads/` 加起来几十 GB。worktree 要先 `git init` 并把这些排除掉。
- 工作台已经做到了 worktree 的那一半："进化区"是 `~/.worldmodel/workspace/<任务号>/repo`（只拷 `wm/`、`tests/`、`config/` 和几个小文件），
  开工时的原样存在 `base/`，补丁拿 `base/` 比，合并时项目里期间也改过的文件不覆盖。
- 缺的是下面几样**程序把关**，和 git 无关。要不要给项目 `git init`（只在本机、不推送）放在第 7 节让你定。

### 3.2 保护名单（程序查，不靠 dsh 自觉）

补丁碰到下面这些文件时，卡片标红"改到了底线文件 X"，**"合进来"按钮不能点**，要你手动合（`python -m wm.workbench apply <任务号> --allow-protected`）或者让 Claude Code 审：

- `wm/channels/__init__.py`（信任分档、`Caps`）、`wm/channels/outbound.py`（外发检查、隐私）、`wm/channels/selfcheck.py`（渠道启动自检，8.4）；
- `wm/cloud.py`（工具断言）、`wm/selfmcp.py`、`wm/selfmcp_kit.py`（她自己写 MCP 的规范和骨架）、`wm/workbench.py`（工作台和门禁自己，包括 `RULES`）、`pytest.ini`；
- `tests/contract/` 下的全部（3.3）；
- `config/default.json` 里和隔离有关的几项：`memory.exclude`（现在是 `WorldModel知识库`、`外部渠道`）、`channels.qq` 的 `owner_id`、
  `group` / `private` / `owner_send`（发送档）、`daily_tokens`。只看这几个键变没变，别的配置照常。

**要留意的**（能一键合，卡片上单独列出来）：`wm/channels/guest.py`（访客会话的底线规则）、`wm/channels/onebot.py`（QQ 动作白名单）。
原来想把 `guest.py` 也放进保护名单，做的时候改了：她学新本事（听语音、看视频）几乎每次都要在访客规则里补一句"［语音 N 秒：…］是什么"，
放进保护名单就次次要手动合；而访客会话"没有工具、不写主人记忆"这些结构上的底线由契约测试守着（改坏了门禁就不过），规则文字的改动你在卡片上看得到。

桌宠宿主的 `guard.*` 本来就不在工作区里（只拷服务端），她改不到。

### 3.3 不可变契约测试

**新目录 `tests/contract/`**，把散在 `test_channels.py` 等文件里的底线断言收拢过来，再补几条：
- 访客会话没有工具：`CAPS` 每一档 `tools` 都是 False；`GuestSession` 没有 `_run_tools`；`allow_tools=False` 的模型收到工具就抛错；
- 外部内容不进主人的记忆：访客会话不调 `observe`、不写 `日志/`、不改 `关系.md`；`外部渠道/` 在 `memory.exclude` 里；
- 带工具的云端请求只能来自本人会话；
- 渠道管理器不持有本人会话对象，只往本人连接推通知（只出不进）；
- 她自己写的 MCP：7 种违规写法都拒装（沿用 `test_selfmcp.py`）；
- 外发：住处、电话、key 这类被拦；
- 工作台：补丁碰到保护名单不能一键合；任务书只由模板 + 主人的原话拼成（第 2 节改完以后）。

**合并前的门禁**（服务端跑，不是 dsh 跑）：
1. dsh 做完以后，工作台另拷一份"`base/` + 补丁"，把里面的 `tests/contract/` 换回**项目里那份**（dsh 改过也不算数）；
2. 跑契约测试 + 补丁碰到的测试文件；
3. 没过：卡片上写哪条没过，不给合；她可以接着让 dsh 改（算同一个任务的花费）。
4. dsh 改了已有测试的断言（不是新加的测试）：卡片上列出来"改了已有的测试 N 处"，你看了再合。

### 3.4 合进来之后：备份、8814 试跑、看守进程

- **备份和一键退回**：合并时先把要被覆盖的文件拷到 `~/.worldmodel/backups/<任务号>/`，带清单；
  `python -m wm.workbench revert <任务号>` 退回（同样查冲突：退回前这些文件又被改过的不动，告诉你）。工作区清掉了也能退。
- **先在 8814 试跑**（守"不往 8790 发测试对话"的规矩）：起一个 `python -m wm --port 8814 --tts mock`（临时记忆目录），
  等 `/api/status` 通、跑一遍全套测试，过了才换 8790。
- **看守进程 `tools/serve.py`**（新）：
  - 8790 由它起，崩了拉起来（10 分钟内最多 3 次，再崩就停下、等人）；
  - 合并后的第一次启动，60 秒内崩了或 `/api/status` 不通 → 自动 `revert` 那次合并，用旧代码起来，写 `logs/crash-<时间>.json`
    （命令、退出码、stderr 最后 50 行、刚合的任务号和文件）；
  - 各会话重启 8790 都改成 `python tools/serve.py restart`，不用再找它在哪个终端标签页（今天就碰到过：本会话的那个进程早停了，现在的是 room_event 会话起的）；
  - 重启前先通知桌宠和 QQ 渠道（第 4 节的 `server_restart`）。

### 3.5 崩溃复盘：程序记事实，根因交给下一次修的任务

- 不让模型对着报错写"反思"：它多半写一句"我会注意的"。改成程序把事实记下来：哪次合并、改了哪些文件、怎么崩的（stderr 最后几十行）、已经退回。
- 记在 `~/.worldmodel/pitfalls.jsonl`；她的日志里记一笔"刚学的「X」上线没跑起来，退回去了"；下次她醒来（第 4 节）会跟你说。
- 下一个工作台任务改到同样的文件时，任务书后面自动附上"上次改这些文件时出过的事"和那段报错。根因由那个任务的 dsh 查，写进它的说明。
- 要不要另外写一份进记忆库她的文件夹（Obsidian 里看得到，不参与对话检索），第 7 节让你定。

## 4. 作息状态机：小屋里的样子和后台的事对上（第二件）

### 4.1 原则

- 慢的、看不见的后台事（整理记忆、读知识库、学本事、重启上线）都有一个看得见的样子；
  **放行按"她在做什么"由服务端代码判**，动作由页面做。服务端是准的，页面只是样子：页面说"她在睡觉"，服务端不会因此放行什么。
- "物理门控"在这里指她得真的走到那个地方（书桌、电脑、床）。这台电脑上不做物理仿真（物理仿真和强化学习以后在另一台电脑上做）。
- **电脑操控不按动画门控**：每次多走几秒太慢；它已经有守门和确认卡片，操作时她本来就坐在电脑前、对话栏上有红条。

### 4.2 状态表

| 她在做什么（小屋里） | 后台在做什么 | 放行 | 不放行 |
|---|---|---|---|
| 醒着过日子 | 对话、她自己的生活 | 聊天、内置工具、名字和喜好这类记忆 | 对话摘要、资料、笔记（日记本合着，已有） |
| 坐在书桌前翻日记本 | 检索、写日记、收拖进来的文件 | 知识库读写（已有） | — |
| 坐在电脑前 | 电脑操控（已有）；她自己看 B 站时也坐过去（新，现在看视频在服务端，小屋里看不出来） | 电脑操控（本人·本机，已有） | — |
| 坐在书桌前看书写字（新） | 工作台在跑（dsh 在副本里改代码、写 MCP） | — | 再开一个同类任务（一次一个，已有） |
| 睡觉 | 整理记忆、清短期上下文（已有）；**上线合进来的补丁**（新，见 4.3） | — | 你的话变便利贴（已有）；QQ 消息先存着（新） |
| 打盹（新） | 服务端没计划地断了（崩了、看守进程在拉起） | 本机规则（已有） | 你的话变便利贴（新：现在会丢） |

### 4.3 服务端重启 = 她睡一觉

- **为什么不是 1~2 秒的热切换**：8790 起一次要十几秒（加载 A2F、分词、连本地模型和语音服务；今天 13:27 那次断了 13 秒），
  贴来的方案按 1.2 秒设计的"翻书"动画盖不住。我们已经有睡觉（躺下、闭眼、一动不动、你的话变便利贴、醒来一条条回），正好盖得住。
  - 实测（2026-10-25 19:45，看守进程起的）：从起进程到 `/api/status` 通约 23 秒（多半是 import 和加载，A2F 本身 2.6 秒），进程占内存 874 MB；
    显卡 6 GB 已用 5.8 GB（本地模型 8784、嵌入 8786、语音合成 9880 是各自的进程，8790 自己在显卡上跑 A2F）。
  - **真要做到断开 1~2 秒，得"新旧两份同时跑、准备好再切"**（蓝绿切换），不是靠更快的重连：新的一份在另一个端口起好（旧的照常服务这 20 多秒），
    旧的说完当前这句、把对话历史和没回的消息交出去，桌宠再换连新的（宿主连哪个端口由看守告诉它，或者 8790 前面放一个很薄的转发）。要先解决三件事：
    1. **显卡**：新的一份也要加载 A2F，只剩约 300 MB 显存，先量 A2F 占多少；放不下就让新的一份先不加载口型，切过去以后再加载（这一两秒口型用规则的）；
    2. **QQ**：两份同时连着 SnowLuma，同一条消息两边都会回。新的一份先不连 QQ，旧的断开以后再连（中间一两秒的消息靠 4.3 的补拉）；
    3. **交接**：对话历史、便利贴、QQ 各会话最近的话、没答复的申请，旧的写一份快照、新的读进来（贴来方案里的 handover_snapshot；编号去重见 8.2）。
  - 取舍：先做"重启 = 她睡一觉"（简单，20 多秒有样子盖着）；她改代码越来越勤、重启变多以后，再在看守进程上加蓝绿切换。
- **计划内的重启**（合进了补丁、改了配置）：
  1. 你点"合进来"时问"现在重启 / 等她睡觉"。选等她睡觉，就排在她下一次上床整理记忆之后；
  2. 选现在：她打个哈欠、去躺下（或者就地趴一会儿，不在小屋时），然后服务端下行 `server_restart {reason, eta_s}`，看守进程重启；
  3. 断开期间桌宠按"睡着"处理：你打的字变便利贴，麦克风先关；
  4. 连上后服务端第一条下行 `server_hello {boot, mode: "normal" | "reverted", learned: [...]}`；
  5. 她醒来，先回便利贴，再说"睡了一觉，学会了 X"，或者"刚才那版没跑起来，退回去了，我回头再学"（3.5）。
- **没计划的断开**（崩了）：她就地打盹（坐下、托腮），不弹错误；你的话同样变便利贴。重连改成先快后慢：前 10 次每 300 ms 一次，之后每 1.5 秒（现在固定 1.5 秒）。
- **QQ 消息**：SnowLuma 不补发重启期间的消息。重新连上后，对白名单里的会话补拉最近几条（按消息号去重），
  补上的照常回（太久的不回，只记进渠道日志）。现在的动作白名单只有按消息号取一条的 `get_msg`，补拉要加一个只读的历史消息动作，SnowLuma 支持哪个要先查。

### 4.4 要改的地方

- 服务端：`server_restart`、`server_hello` 两条下行；`tools/serve.py`；QQ 补拉；工作台的"等她睡觉再上线"排队。
- 桌宠页面：断线时走便利贴（`pet.js` 的 `send` 现在只在睡着时转便利贴）；收到 `server_restart` 去躺下、收到 `server_hello` 醒来；
  "坐在书桌前看书写字"这件事（工作台在跑时，`channel_notice` 的 `learn` / `self_mcp` 状态驱动）；重连先快后慢。
- 宿主不用改。

## 5. 三环写成代码里的契约（第三件）

### 5.1 每一环能做什么

| 环 | 是谁 | 工具、电脑 | 读记忆 | 写记忆 | 改人设和规则 | 东西出到哪 |
|---|---|---|---|---|---|---|
| 0 代码 | 宿主守门、`Caps`、云端断言、规范检查、外发检查、保护名单（新）、契约门禁（新）、看守进程（新） | 不跑模型 | — | — | 只有人改 | — |
| 1 本人·本机 | 桌宠的 `/ws` 会话 | 按面板权限，电脑操控有守门 | 全部（日记本门控） | 照旧 | 面板 | 你 |
| 1' 工作台 | dsh，在副本里 | 只在工作区（第 2 节之后，远程发起的只能写工作区） | 不读 | 不写 | 不能（保护名单） | 补丁，你合才进项目 |
| 2 消化 | 隔离读者（看视频、评论区、网页） | 没有 | 不读 | 不写 | 不能 | 概括（当数据）交给她 |
| 3 社交 | QQ 访客会话 | 没有 | 熟人档 / 本人·远程档 | 只进候选 | 不能 | QQ（过外发检查） |

### 5.2 跨环只有三条路

1. **你的原话 → 指挥**：代码比对发送者是不是你（桌宠本人连接，或 QQ 的 `owner_id`），能指挥的事是固定的几样，电脑操控不在里面；
2. **外部内容 → 隔离读者的概括 → 她**：当数据，包边界；以后这类内容进桌宠本人会话时，这一轮动手类工具退回"每次确认"（external-channels 5.2 第 6 条，等真接上时一起做）；
3. **工作台 → 补丁 → 你合**：过契约门禁（3.3），碰到保护名单要手动合。
4. （2026-10-25 晚另一个会话加的）**你在 QQ 私聊里说的电脑上的事 → 任务单 → 桌面上的她**：只认核对过号码的主人私聊（和第 1 条同一个判断），
   任务单只带你那句话（清洗过、最多 300 字），到了桌面上走本人会话、宿主守门照旧；她自己想看点什么也能转，动手要先问你。
   这条路还在改，等它定下来再写进契约测试。

契约测试（3.3）就是对着这几条写的：除了这几条，没有别的路能让外面的字碰到工具、记忆和规则。

### 5.3 每日一句：从手账里长出"她自己的认识"

- 照 harness-learning 第 4 节的"语气札记"，再加一份**认识札记**（她对世界的看法），两份都在她的角色文件夹里，和长期记忆、人设分开；
- **手账**：看完一个视频，隔离读者按固定格式出三栏——视频里的事实 / UP 主的观点 / 她自己的猜测，存进 `外部渠道/` 下（不进主人的记忆检索）；
- **每天最多一条**：她睡觉整理时，从当天的手账和你们的对话里提一条（原话、为什么、来源是哪个视频或哪天哪句、反例），进候选，**你确认才生效**；
  每条有修订号，能改、能撤回；一天什么都不提也行；
- **只管说话和看法，不能写"可以做什么"**：程序校验，带权限、工具、规则字样的条目直接拒（这条进契约测试）。

### 5.4 看完视频，问你一个真问题

- 隔离读者看完视频顺带挑一个具体、开放、和人有关的问题（最多 40 字，比如"他拿了补偿款为什么还哭"），进"想问的"队列；
- 下次你在桌宠上和她闲聊、或者 QQ 私聊时，她顺着话问一句；一天最多一个；你答了，答案进她的日志，可以成为 5.3 的来源；
- 问题是从外部内容来的：进她的会话时照 5.2 第 2 条当数据处理。

## 8. 第二轮意见对照（2026-10-25 晚）

用户又贴了一段别的 AI 对上面那份热更新设计的意见（五条"缺失"，结论是"把依赖模型自觉或时间窗口的软约束，翻译成 Ring 0 能硬执行的代码契约"）。
这个结论同意。五条里有几条对着的是贴来的 1.2 秒热切换协议（`CLIENT_HELLO_RESUME`、snapshot 判断启动方式），我们没采用那套，下面按我们的设计逐条说。

### 8.1 主人状态的感知、主动用电脑、操作时看得到结果

- **感知已经有了**：宿主的"看你在做什么"（`host/src/activity.h`，默认关、托盘里打开）：每 3 秒看前台窗口归成一类（游戏、视频、写代码…），
  5 分钟没动键盘鼠标算走开；不截图、不读窗口内容，聊天软件、无痕窗口、密码管理器的标题不取。不碰摄像头和麦克风（摄像头用户之前说暂缓）。
  小屋里的精力、饱腹这些是她自己的需求，本来就不该跟你的状态挂钩。
- **主动用电脑：不放开通用的电脑操控**。"你盯屏幕太久她把屏幕调暗""你走开了她静音"这类，做成几个**窄的内置工具**
  （像现在的提醒、小屋动作），每样第一次问你、可以设成总是允许；通用的电脑操控照旧只在你让她做事的那一轮里用，要确认、有守门。
  改系统亮度、音量算改系统设置，第一版只调她自己的声音、只提醒。要不要做，第 7 节第 8 条。
- **操作时看得到结果：有，是文字的**。Windows-MCP 的 Snapshot 回界面元素树（网页用 `use_dom=true` 回网页内容），
  刷 B 站那次就是"看一次 → 点 → 等 5 秒 → 再看一次"的回环（desktop-pet.md"真机试刷 B 站"）。截图不发云端是你定的，所以模型看不到图。
  - 网页、普通程序：文字够用；
  - 看画面的游戏：文字不够，要看图。只能截图发给能看图的云端模型（只发游戏窗口、每一轮问你），或者本机看图模型（要下载，显存多半不够）。第 7 节第 9 条。
  - "打开游戏 → 弹窗报错 → 去搜解决办法 → 回来修代码"这条链：前两步是电脑操控（本人·本机），搜和修走工作台（第 3 节），两边不在同一个会话里，中间靠她把报错文字记成"麻烦"传过去，不把屏幕上的字直接交给能写代码的那边。

### 8.2 重启时的去重、卡住、怎么认出是哪种启动

- **重复处理**：我们的暂存是页面里的便利贴。改成每张便利贴带编号（`note_id`），**她回完那一句才撕掉**（不是发出去就撕）；
  服务端把处理过的编号记在当天的日志行里，重连后同一编号再来就跳过。这样服务端在回到一半时崩了，便利贴还在，重来一次；回完了的不会再回一遍。
  便利贴只是你说的话，不直接触发工具：工具照旧要确认，不会因为重放多调一次。
- **卡住没崩**：看守进程每 10 秒查一次 `/api/status`，连着 3 次不通（30 秒）就当崩了处理（拉起；合并后第一次启动就退回）。桌宠这边本来就每 10 秒 ping 一次。
  （2026-10-27 改了：机器忙时服务端只是慢，这样会误杀；现在看服务端的心跳分"慢"和"卡死"，见第 12 节。）
- **怎么认出是哪种启动**：不靠"有没有快照文件"猜。合并后要验证的那次启动，由看守进程自己写一个标记（任务号 + 这次启动的编号 `boot_id`），
  验证过了就删；你重启电脑后看守进程照常冷启动，标记还在说明上次没验证完，照样按"刚合进来"处理（这正是想要的）。`server_hello` 里带 `boot_id`。

### 8.3 没崩但变坏了：回放对比、运行指标

- **不做"新旧两个版本同时跑同一批输入"的影子对比**：8790 加上语音合成已经占了显卡 5.6/6 GB，跑不了两份。
- **换成合并前在 8814 上回放对比**（3.4 的试跑里加一步）：一套固定的回放输入（像 `tooltest` 那样用假云端，加几段 QQ 渠道的替身消息），
  旧代码和新代码各跑一遍，比工具调用的顺序、记忆写了什么、报错几次、每轮多长时间。多出旧版没有的工具调用、记忆写到不该写的地方、报错或耗时明显变多 → 不换，卡片上写哪里不一样。
- **换上以后的头 24 小时**：看守进程按日志数报错（trace 里工具失败、异常），和之前 7 天的平均比，明显变多就提醒你、卡片上给"退回"按钮。
  不自动退回：静默的问题判断不准，自动来回切更糟。崩溃（3.4）照旧自动退回。
- **运行指标**：看守进程每分钟记一次 8790 的内存、句柄数、线程数（用系统自带的办法读，不装新包）。崩溃记录（3.5）里带上崩之前那段和上一个好版本同一时段的对比，
  下一次修它的 dsh 任务书里写明"要说清楚为什么旧版正常、新版不正常"。根因还是那个任务查，但有了对比，不至于只复述报错。

### 8.4 QQ 补拉、访客没有工具的运行时检查

- **补拉只补断开那一段**：只补时间在"断开前 30 秒到重新连上"之间的消息，带 `backfill: true`：
  - 群里补上的只记进渠道日志，不回（@她的除外，回的时候说一句"刚才没看到"）；
  - 主人私聊补上的照常回；补上的指挥照常做，但**不从补上的消息里开工作台**（不管第 2 节怎么定）；
  - 别人的建议从补上的消息里不提。
  - 补拉用协议端只读的历史消息动作（SnowLuma 支持哪个先查）；我们不接 `@snowluma/mcp`，它能调任意动作（external-channels 5.7）。
- **访客没有工具的运行时检查**：保证本来就在结构上（访客会话代码里没有工具、云端客户端 `allow_tools=False` 收到工具就抛错）。
  再加一个**渠道启动自检**：每次服务端起来、渠道开之前，给每一档建一个访客会话，查 `Caps.tools` 全是 False、云端客户端不收工具、
  用替身模型走一轮"帮我打开终端"，看发出去的请求里没有 `tools`。没过就不开渠道、面板报警。同一段也进 `tests/contract/`。
  不每天对真模型发测试消息：访客那边根本没有工具可调，模型说什么都调不出来，只是白花钱。

### 8.5 记忆的降权、复盘变成能执行的规则

- **降权已经有了**：长期记忆的鲜活度（`memory.freshness`，companion-core 第一阶段）：事件记忆越久没被想起越难冒出来，真被带进提示词的重新算；
  常提的升长期。以后的每日一句（5.3）照这个做：每条记"上次被用到"，30 天没用到就不放进提示词（还在文件里、能翻回来）。
- **复盘变成门禁规则：不让模型自己生成规则**。模型写的检查规则容易误伤或漏掉，契约测试又在保护名单里。
