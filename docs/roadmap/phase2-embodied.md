# 阶段二立项: 具身场 — 同一个意图在物理本体上时序一致地复现

## 1. 目标与成功标准

把陪伴场已经跑通的"意图 -> 运动 -> 状态"闭环换一个执行器: 先在物理仿真里, 再到实体机器人. 成功标准不是"机器人会干活",
而是 **同一句话产生的同一个意图, 在运动学本体 (VRM) 和物理本体上产生时序一致、物理可行的运动**:

| 指标 | 目标 |
|---|---|
| 仿真里能跟住的动作 (站立/走/转身/坐下/站起/捡放/挥手/点头) | 8 类里至少 6 类, 每类成功率 >= 90% (不摔、不穿模、关键帧误差 < 5 cm) |
| 意图到物理动作开始的延迟 | 不超过运动学本体 +100 ms |
| 同一意图在两个本体上的关键帧时间差 | P95 < 200 ms |
| 运动学参考里物理不可行的姿态 | 被识别并修正, 不让策略硬跟 |

## 2. 现状与依据

- 陪伴场已有: 意图协议 (`do/side/to/amp/spd/at` + 置信度)、运动匹配和动作片段 (CMU、100STYLE 重定向到 VRM)、
  接触与碰撞层、坐姿/持物约束、延迟埋点.
- 已验证的负面结果 (README "可行性验证"): ProtoMotions 现成的 MaskedMimic (SMPL) 模型在本机 MuJoCo 里站不住.
  说明运动学闭环和物理闭环之间有真实的鸿沟, 要靠在目标仿真器里训练的跟踪策略来跨过, 不能直接拿现成模型.
- 可参考的方向 (用户提供的材料, 标"待核实"的还没看原文/代码):
  - 物理跟踪策略: ProtoMotions/MaskedMimic (已验证可运行, 但要重训); Mimic2DM、SMP (待核实, 从视频/2D 关键点学物理可控角色).
  - 文本到运动 + 物理跟踪: NVIDIA ARDY + SONIC 跟踪策略 (已核实 ARDY 存在, 有 Unitree G1 版本); TextOp (已核实存在,
    高层自回归扩散 + 低层跟踪策略, 代码许可待核实).
  - 人类视频到机器人技能迁移: XPACE、CapPro、HSImul3R (待核实).
  - 可商用的人体模型: Meta MHR (Apache-2.0, 已核实); NAVER Anny (待核实).

## 3. 范围

做:
1. 仿真本体: 先选一个开源人形 (MuJoCo 里的 SMPL-like 人形或 Unitree G1 模型), 以 MuJoCo 为主, Newton 为备选.
2. 参考运动: 陪伴场的运动学输出 (运动匹配 + 动作片段 + 接触层修正后的骨骼流) 重定向到仿真本体.
3. 跟踪策略: 在目标仿真器里训练通用运动跟踪策略 (PPO, 参考 PHC/MaskedMimic 的做法), 训练数据用许可干净的动捕
   (CMU 可商用部分、100STYLE CC BY、StayStill MIT、自录动捕).
4. 可行性过滤: 跟踪失败的参考片段回流到运动学层, 标成"该本体不可行", 意图协议里回报.
5. 意图路由: 同一个意图同时发给 VRM 和仿真本体, 比较两边的关键帧时间.

不做 (本阶段):
- 灵巧手操作、从零训练 VLA、实体机器人上的长时间无人值守运行.

## 4. 里程碑

| 里程碑 | 内容 | 产出 | 预计 |
|---|---|---|---|
| M0 环境 | MuJoCo 人形 + 重定向管线 (VRM 骨骼流 -> 仿真关节), 回放运动学参考 (不加物理) | 可视化对照 | 1-2 周 |
| M1 跟踪 | 在本机/云 GPU 上训练跟踪策略, 8 类动作在仿真里跟住 | 策略权重 + 成功率报告 | 3-6 周 |
| M2 闭环 | 意图同时驱动 VRM 和仿真本体, 埋点记录两边关键帧 | 时间差报告 | 1-2 周 |
| M3 可行性回流 | 跟不住的片段自动标注, 运动学层避开 | 可行性表 + 协议字段 | 1-2 周 |
| M4 实体 (可选) | 选一款开放 SDK 的人形或机械臂, 在实体上复现 M2 | 实机视频 + 安全规程 | 视硬件 |

## 5. 资源与依赖

- 算力: RTX 3060 Laptop 6 GB 只够推理和小规模训练; 跟踪策略训练建议云上 1 张 24 GB 以上的卡 (数天量级).
- 下载 (届时逐项列清单确认): MuJoCo (Apache-2.0)、人形模型、PyTorch CUDA 版、训练用动捕.
- 依赖阶段一: 接触与碰撞层、意图协议的置信度字段、埋点.

## 6. 风险

| 风险 | 应对 |
|---|---|
| 训练数据许可 (AMASS/SMPL 系非商业) | 只用可商用数据训练; SMPL 系模型只做对照 |
| 跟踪策略在本机算力上训练太慢 | M1 上云; 本机只做推理和评估 |
| 运动学参考物理不可行 (滑步、穿模、重心越界) | 先过接触层和可行性过滤, 跟不住的回流标注 |
| 仿真到实物的差距 | M4 之前不承诺实体效果; 选 SDK 开放、社区有现成 sim2real 经验的平台 |

## 7. 决策点

- M0 结束: 选定仿真本体 (人形 vs G1) 和仿真器 (MuJoCo vs Newton).
- M1 中期: 若 6 类以上动作 3 周内跟不住, 改用"运动学 + 物理后处理 (只修脚部接触和重心)"的折中方案.
- M3 结束: 决定是否进入 M4 实体.
