### 保存顺序与故障边界

先把液体世界的数量变化和待结算回执一起持久化，再用一次 Needs 存储写入同时提交需求效果与已处理序号，最后移除内存待办。任一步保存失败都不确认该回执，重载仍用同一 ID 重试；已经提交的事件只确认，不重复奖励。咖啡脚本收尾显式检查保存与待办队列，区分“实际喝到”和“效果尚未保存”。原 `needs.use('beans')` 与脚本结束固定水分/精力奖励在新模式下不再参与这条消费链。

## 建议采用的方向

把“生活仿真”和“学会控制身体”连接起来，但分别建模。进食、生病等是虚拟人生活的一种表现；状态估计、资源管理、接触操作、受限条件下的动作选择与失败恢复，可以作为机器人迁移研究的任务与方法；能否迁移仍需独立实机验证。让机器人理解人类什么时候需要食物、如何端水和准备食材，也不要求机器人本身长出消化系统。

第一版实现可解释的饥饿、口渴、疲劳、舒适度及恢复，并沿用已经存在的烫伤/湿润/握力反馈。疾病作为可选的虚拟情节层，后续有明确学习任务再加入。药品和输液不应成为统一“恢复全部数值”的按钮；暂不制作真实药品剂量、疾病诊断或治疗策略。护理场景先研究取水、搬运、摆放、协助休息等动作。

同一个角色换房间后，个人需求、练习和身体状态应延续；家具位置、液体、物件姿态、发现簿与空间经验按房间隔离。未来物品库存需要有实例身份和迁移记录，不能通过换场景免费刷新食物。本轮沿用已有个人库存，不因进入 V8 重发初始饮料。

| 层 | 状态与输入 | 用途 | 不应混入的内容 |
|---|---|---|---|
| 角色生活 | 饱腹、水分、疲劳、舒适、心境、偏好 | 生活节奏、情绪表达、活动选择 | 真实 API 余额、任意改动权限 |

保持环境真值、她感知到的证据、她对原因的判断三份记录。一个“肚子不舒服”的感受不自动揭示病原、具体食物或诊断；她可以形成带置信度的假设，通过观察和对话更新。现实健康知识另有来源和版本，不能由自编游戏规则覆盖。

## 食物怎样产生后果

每个物品实例至少包含 `item_id / batch_id / quantity / ingredients / preparation / temperature / storage_history / owner_scene`。将冷热、加工状态、污染风险和个人喜好分开：冷热是温度，生熟是加工结果，是否受到污染需要另外的信息。WHO 的食品安全资料把食源危害涉及的细菌、病毒、寄生虫和化学物质分别说明，因此不应将“冷”“生”直接编码为统一疾病标签。[WHO 食品安全](https://www.who.int/news-room/fact-sheets/detail/food-safety)

建议事件事务为：

`预留一份 → 拿取 → 准备/加热/冷却 → 实际入口 → 结算已消费数量 → 延迟效果 → 剩余物归位`

每笔 `consume_event` 有唯一 ID、来源物品、实际消费量、时间、结算版本和完成状态。重放、断网重试、重复回调不得再增加效果；洒出的部分、空杯动作、拿起又放回都不是消费。中断时提交已经完成的部分，保留剩余量，不同时把整份库存和杯中液量各扣一次。

物品隐藏成分、未经观察的储存史与精确身体极限属于环境/评估真值；策略只能获得公开标签、实际观察、身体感觉，以及带置信度的估计。环境内部的数量可以精确，展示给角色的身体感觉是有噪声、延迟和可观察范围的。例如她可以感到口渴缓解，不能因此立刻知道饮料配方中的隐藏成分。

先做统一效果定义：`effect_id / onset / duration / magnitude / stack_group / max_stack / decay / provenance`。同组有上限和递减，清除或替换行为可追踪。参数先用游戏单位并明确版本，不标作人体医学定量模型。

| 对象 | 可以设计的生活效果 | 可能影响的动作/规划 | 必须测的反例 |
|---|---|---|---|
| 水/饮料 | 缓解口渴，口味偏好有差异 | 去哪里拿、取多少、是否需要杯子 | 已不渴仍反复喝、空杯获益、重复回调 |
| 零食/食物 | 饱腹、有限愉悦、延迟消化效果 | 单/双手拿取、开包装、用餐姿态 | 无限叠加愉悦、未入口就补满 |
| 咖啡 | 可选的短时清醒表现与后续恢复需求 | 在预算内选择活动强度，端热液体时选择稳妥策略 | 把疲劳永久清零、把喝咖啡当算力升级 |
| 温度变化 | 接触舒适度和现有热伤后果 | 握把、换手、隔热物、等候或少装 | “温热能治所有不适”、没有接触也受伤 |

厨房与菜地接在同一物品账本：种子→生长批次→收获实例→储存→配方投入→加工产物→消费。菜园可以训练长期规划、等待与资源分配；厨房训练多物体操作、容器转移、流程依赖与清理。每一步都需要数量守恒或显式损耗，不能用点击菜单直接生成成品替代执行证据。

## 奖励、情绪与 token 各自承担什么

采用向量反馈，先分别记录任务、身体需要、探索、资源与风险，再为具体任务配置权重。不要只留一个总分，使“完成拿放但洒光了”和“安全放下但没有完成任务”无法区分。

以内部状态偏离舒适范围的程度 `D(h)` 表示需求代价。建议工程起点：

```
r_need = D(同一时段没有该消费动作的状态) - D(实际状态)
r = w_task*r_task + w_need*r_need + w_information*r_information
    - w_resource*resource_cost - w_risk*risk_cost
```

反事实比较必须固定同一初态、外部随机性和评估时域，记录不消费的对照策略。可以先在离线仿真中计算，再决定哪些反馈进入训练；不得把反事实隐藏状态作为角色观察。还要与简单的消费前后需求差值作对照，不能预先宣称更有效。

这是本项目提出的可测试设计，不是已证明不会被利用的奖励函数。反事实基线、时间折扣、终止条件及权重都会改变行为；需要专门测试等待饥饿再吃、制造事故再修复、故意诱发不适以获得照顾等循环。必要时给安全条件独立硬约束，不能靠增加总奖励抵消违规。

内稳态强化学习研究提供了“内部需求影响奖励价值”的理论基础，并不证明桌宠已经会自主学习，也不提供完整人体生理模拟。[Keramati 与 Gutkin，eLife 2014](https://pmc.ncbi.nlm.nih.gov/articles/PMC4270100/)

情绪应综合近期结果、预期落差、身体感觉、偏好和交互，而非直接将总奖励映射为笑脸。主观报告可说“轻松些了”“想休息”，不必输出所有后台数值。身体不舒服可以改变表达与活动选择，不应通过故意增加幻觉、降低事实准确性来表现“生病”。

失败还需要原因归属：控制器缺陷、物体属性、环境布局、身体条件或未知，分别记录置信度和证据。拿书撞架不能直接教成“这本书不好看”；杯子没送到嘴边不能直接教成“不喜欢咖啡”。工程诊断可以读真值定位 bug，角色仍只依据自己的观察更新假设；修复控制器后应重核相关偏好和技能结论，避免把实现错误固化为世界知识。

真实 token 是推理资源，游戏积分是设计变量。将两者使用不同名称和账本。用户设置的金额、时长和调用上限是外部预算；食物只能影响预算内的注意分配，例如主动观察还是休息，不能扩大授权额度或宣称提升模型智力。真实上下文压缩、缓存命中与模型训练另按实际指标优化。

## “生病”应怎样逐级加入

1. **可恢复身体条件**：疲劳、短时不适、已有烫伤/湿润；有明确诱因、延迟、恢复过程和强度上限。先验证动作约束和生活决策。
2. **可选人类生活情节**：虚拟病假、照顾、康复活动。情节与环境模型显式标记为模拟，不将随机抽签患病当作理解疾病。
3. **有来源的人类知识学习**：把饮食卫生、辨别风险、寻找可靠帮助等作为知识与规划任务；区分已知、未知与推测。不要用模型生成的医学因果直接更新环境引擎。
4. **医疗互动扩展**：只有明确场景与专业校验后，再考虑药品、器械或护理流程。当前不建立真实药物剂量规则；输液也不是默认恢复方式。

是否开启生活疾病由用户选择；恢复途径应允许她自主处理基本休息和补给。离线恢复有上限，不把用户离开期间累计病情当成日后惩罚。研究模式的困难条件与日常陪伴模式分开，避免为了训练不断让日常角色受伤。

## 怎样才真正帮助动作模型

控制器接收结构化能力约束，而不是单一“生病/健康”标签：

`CapabilityEnvelope = {joint_limits, strength_limits, speed_limits, grip_limits, balance_limits, support_requirements}`

这些条件要在仿真转移和求解器中实际生效。环境约束可用精确值；面向部分可观测控制的策略应输入校准/估计能力及置信度。另设直接提供真值的对照组，不能把它的收益归为自主感知或推断能力。例如降低右手握力后，单手搬运可能失败，策略需要选择双手、减小负载或更换抓点；约束腿部范围后，原来的坐姿可能不可达，需要重选站位和动作。给标签却不改变动力学，只能训练标签响应或风格，不能证明鲁棒控制改善。

当前项目以运动学动作、IK 和接触修正为主，加入 Rapier 小物体并不等于全身已有力矩驱动。第一阶段可做约束规划/残差纠正；真正的全身动力学训练需要质量、惯量、关节、驱动器和接触模型，另设训练环境，再评估蒸馏成浏览器小模型是否可行。没有这一步，不能把数值姿态修正称为机器人控制迁移。

建议实验顺序：

- **基准任务**：端杯、不同高度拿放、坐下起立、取书；先保证健康基线可完成。旧房间 Library01 的表面抓握契约/全身可达性仍有未通过项，旧默认取读还流程能完成并不等于没有碰撞；V8 取书需独立验收，不能沿用旧结果。不能用身体状态实验掩盖基线失败。
- **条件课程**：逐项改变握力、物体重量、摩擦、可达范围、接触约束，再组合；使用对称/左右手/多体型对照。
- **分组比较**：不带状态的控制器；仅情绪/姿态风格；只在训练随机扰动；显式条件控制器。检验哪个组成产生收益。
- **持出评估**：按体型、动作片段、物体和布局划分，不能把同一片段的多个种子当多个独立样本。保留未见参数区间与组合条件。
- **指标**：实际完成率、接触误差、穿透、腕部范围、支撑稳定、洒落、时间、失败恢复，以及资源成本。报告最差分组与区间；因回避所有任务而“没有受伤”不能算通过。

推荐的研究参照是控制链，而不是单看演示画面：

## 本项目落地顺序

先完成 V8 的坐标、碰撞、感知和场景隔离验收，再核对一次消费只结算一次、实际入口量和状态变化。随后加入带版本的效果定义与可解释选择日志。得到健康基线后，离线做能力约束的控制变量实验；只有持出任务证明确实提高成功率或恢复能力，才把训练结果作为候选进入现有验收门。

这条路线把生活仿真作为可测的具身任务来源，同时保留人类知识的事实边界、角色的连续身份和真实推理预算的控制权。
