# 桌宠的 harness：从 AstrBot 启动器、DSH Desktop、OhWhale、bili-humanism 学什么

2026-10-25 调研。看了本机装好的 AstrBot 启动器 0.3.10 的界面和它的源码（MIT），读了下面几个仓库的 README 和文档（只读，没下载、没装）。

用户的原话："我觉得需要学习 astrbot 的界面和 ui 设计，包括'实例、版本、备份'三个部分，然后测试其他的功能是否能够使用，其实就像 dsh 那样，他有一个自带的高命中率的 harness，支持完全权限控制电脑设备，甚至可以自己给自己编程、开发 mcp 或者插件等等，并主动通过跟人对话迭代自己的说话语气，以变得更像人类发言。"另外问了 `dsh-desktop` 能不能拿来完善桌宠的 harness、`dsh-our-free-model` 是什么。

## 1. AstrBot 启动器：实例、版本、备份

本机装的 0.3.10，六页：实例、版本、备份、日志、高级、关于。

**实例页**：表格一行一个实例，列"名称、状态、端口、版本、操作"。操作是五个图标：启动/停止、打开目录、看日志、设置（名称、版本、WebUI 监听地址和端口）、删除。第一次启动时从 AstrBot 的启动日志里抓出初始密码，弹窗显示一次（"wm-guest 默认账户密码"）。

**版本页**分三块：
- 组件管理：Python（3.10 / 3.12 运行时）、Node.js、uv，各自"已下载 / 未下载"，能重装、删除；
- 已下载的版本：版本号 + 日期，能看说明、删除；
- 可下载的版本：从发布页拉的列表，一键下载。

**备份页**：表格列"实例名称（状态：正常 / 损坏）、版本、创建时间、备注、操作（恢复、删除）"，右上角"创建备份"选实例。实测建了一份：5.4 MB 的 zip，里面是 `backup.toml`（创建时间、实例、版本、`includes_venv = false`、`includes_data = true`、`auto_generated`）加整个 `data/`。**注意：备份里有 `cmd_config.json`，也就带着访客 token 和 WebUI 密码的哈希**，不要外传。

源码里（`src-tauri/src/backup.rs`、`instance/lifecycle.rs`）还有界面上看不出的几件事：
- 升级、降级前自动备份（文件名带 `-auto`），恢复成功后自动删掉这份；
- 启动时找"没收尾的自动备份"，认出上次升级中断了，提示恢复；
- 备份跳过 `__pycache__`，恢复时按条目逐个放回，不认识的条目跳过并记日志；
- 实例进程挂在 Windows 作业对象里，启动器退出时一起结束；靠日志里的"启动完成"行判断起来没有，超时就取消。

**日志页**：来源（系统 / 各实例）+ 级别筛选 + 清空，深色等宽。**高级页**：外观主题、关窗时最小化到托盘、版本更新检查、退出时记住运行状态、开机自启、中国大陆一键加速、用 uv 装依赖、文件锁检测、数据目录（打开 / 更改）、代理、GitHub / PyPI / Node / npm 镜像源、故障排除（清空 data、清空虚拟环境、清空 Python 缓存、清 uv 缓存）。**关于页**：版本、"更新到 v0.3.13"、更新内容。

**我们拿来做什么**（面板加一页"版本与备份"，要用户定）：

| 启动器 | 我们对应的东西 |
|---|---|
| 实例 | 服务端（8790）、桌宠宿主、本地模型（8784）、TTS（9880）：一行一个，状态、端口、版本、启停、看日志 |
| 组件 | Python、llama.cpp、GPT-SoVITS 运行时、WebView2、模型文件（带 SHA-256） |
| 版本 | `build\bin` 的桌宠、服务端代码的版本；以后发布了才有"可下载的版本" |
| 备份 | 记忆库（角色文件夹）、`pet-settings.json`、人设预设、扩展包。只备数据不备环境，带清单；**升级前、整理记忆前自动备份**，中断了下次启动提示恢复 |
| 故障排除 | 清 WebView2 缓存、重建语义索引、重置面板设置（先备份） |

## 2. DSH Desktop：dsh 的桌面外壳

架构（`docs/architecture.md`）：Electron 主进程起一个独立的、能跑 Node 的 Harness 进程，Harness 的网页界面只听 `127.0.0.1` 的随机端口，主窗口是沙箱化的 BrowserWindow（关 Node、开上下文隔离、挡 webview、限制跳转、权限白名单）。数据都在 Electron 的用户数据目录（profiles、sessions、settings.yaml、插件），升级不动它们。

值得学的几件：
1. **安全模式**：另起一个只含官方核心插件的 profile，第三方插件全挡，会话、模型设置、工作区照常能用；可以在安全模式里删掉选中的插件再回到正常启动。不删任何东西。
   - 我们：宿主加 `--safe-mode`，不加载面板里配的 MCP 服务器、skill 和扩展包，只留内置工具。扩展出问题时用户能自救。
2. **插件故障归因**：启动或渲染失败时，从日志和页面的证据、清单、依赖里找出是哪个插件，给针对性的操作；破坏性的改动要用户点。
   - 我们：MCP 服务器起不来、扩展包坏了时，面板直接说是哪个、给"停用 / 删除"。
3. **预设包 `.dshpreset`**：zip（`manifest.json` + 预设 YAML）。导入分两步：先校验和预览，确认后才写；同名不覆盖，要换名字；先写临时目录再原子挪过去；拒绝绝对路径、`..`、反斜杠路径、超大包。**明说"预设就是可执行配置"**，可能带插件和能跑命令的工具，只装可信来源的；导出不带 key、凭据、会话。
   - 我们：扩展中心 E1 的 `.wmext` 已经是"预览全文、SHA-256、确认才装"，可以补上"同名不覆盖、拒绝路径穿越、导出不带 key"三条（已有的要核对）。
4. **手机配对**：Harness 本体不改监听地址；手机走单独的配对桥，短时随机 token，Wi-Fi 扫码即连，走公网隧道还要电脑上显示的 6 位码（默认 5 分钟、只在内存里）；断开即作废。
   - 我们：以后"手机找她"照这个边界做：本机接口不对外，另起配对桥，只放行聊天那一小块。
5. **更新**：启动后和每 6 小时查一次，先问再下，下完再问"重启并安装"，能跳过某一版。

## 3. 桌宠的 harness：dsh 能做的 vs 我们现在

用户说的 dsh 那几样能力，对着我们现在：

| 能力 | dsh | 我们现在 | 建议 |
|---|---|---|---|
| 操控电脑 | 本体的 shell、文件、代码工具，在它自己的沙箱里 | 有：Windows-MCP + 宿主守门 + 四档权限，聊天软件一律不碰（"让桌宠真的能操控电脑和手机"那个会话做的） | 照现在的守门走，不加"完全权限" |
| 自己给自己写代码、写 MCP / 插件 | 能写文件、跑命令，插件装进 profile | 没有 | **给她一个工作区**：只能在 `%APPDATA%\WorldModel\workspace` 里写 skill、MCP 原型和测试；写出来的东西按第三方扩展对待，走扩展中心"预览 → 你确认 → 装"；**不能改宿主、服务端、人设和"宪法"**，不能给自己加权限 |
| 插件市场 | dsh-market 社区市场 | 扩展中心 E1（内置工具、内容包、调用记录），市场 E2 / E3 待做 | 照 [extensions.md](extensions.md) 的分步 |
| 跟人对话迭代说话语气 | 社区插件做（bili-humanism 的人格积累、talk-normal 去 AI 腔） | 陪伴底层第三阶段"人设分层 + 去 AI 腔"还没做；有候选记忆（你确认才进长记忆） | **"语气札记"**，见第 4 节 |
| 安全模式、故障归因 | DSH Desktop | 没有 | 第 2 节第 1、2 条 |
| 版本与备份 | DSH Desktop 的升级保留数据；AstrBot 启动器的备份 | 没有统一的 | 第 1 节 |

"高命中率"没有现成的指标可抄，dsh 也没公开过数字。我们自己量：工具调用成功率、一次就选对工具的比例、要用户纠正的次数，进 `tooltest` 和日志统计。

## 4. 语气札记：从对话里改说话方式，但有闸门

照 bili-humanism 的人格积累，和我们已有的"候选记忆""外部来源不能改宪法"合起来：

- **放哪**：角色文件夹里单独一个 `语气札记.md`，不和长记忆、人设混；人设里只留一句"说话前按需读语气札记"。
- **从哪来**：只从**你**的对话和你的反馈（"别这么说""这样说挺好"）来。QQ 群、AstrBot 那边的外部消息不能产生语气条目（和外部消息不进记忆同一条规矩）。
- **怎么进**：每天最多一条；她先提议（原话、为什么、反例、来源是哪天哪句），进候选；**你确认才生效**；每条能改、能撤回，留修订记录。允许一天什么都不选。
- **不能干什么**：语气条目只管说话方式，不能写"可以做什么"；程序校验，带权限、工具、规则字样的条目直接拒。
- **怎么看效果**：去 AI 腔的回归集（talk-normal 那种"每条规则有回归记录"）；同一批问题前后对比字数、客服腔句式出现次数。

这一条落在陪伴底层第三阶段（[companion-core.md](companion-core.md)），做之前要用户定。

## 5. dsh-our-free-model 是什么

- **怎么做到"免费不限量"**（按它自己的 README）：
  - 免费车道：OpenCode 的 Zen 网关；Kilo AI 公共网关的免费模型池。**Kilo 自己在模型卡里写了 prompt 可能被记录用于改进服务**；
  - **十个账号渠道**：LobsterAI（有道）、Qoder（阿里）、TRAE（字节）、Cline、Loomy（讯飞）、Raccoon（商汤）、MiniMax Code、ZCode（智谱）、Gemini Code Assist 等编程助手的账号，账号池、每日领积分。这是把这些产品给自家客户端的免费额度接出来给别的程序用，**多半违反它们的服务条款**，账号可能被封；
  - "EAC 渠道"：协付通道，要用 GitHub 登录并 star 这个仓库才放行，凭据"由宿主指纹闸门把守"，钱和数据怎么走看不清。
- **另外几个风险**：公告中心由维护者远程推送 HTML（`urgent` 级弹全屏）；应用内一键升级 + 热重载，等于维护者随时能换掉你机器上跑的代码；README 自己说 npm 上同名的包是第三方改过的。
- **结论：不接。**她的对话里有你的记忆和隐私，不能发给记录 prompt 的免费池；靠别人免费额度的通道随时会断。云端模型继续用你自己的 key（DeepSeek / Qwen / Kimi 预设）。
- **能借的工程点**：
  - 只列真能路由的模型（探测时区分"模型不存在"和"网关故障 / 限流"，后者不算模型不可用）；
  - 思考强度按模型自己的档位真实下发；
  - 降级链：正文输出之前失败才切下一个，切换对调用方不可见；
  - 工具输出压缩：`git diff`、日志这类结果在发给模型前就地精简（它实测省 90% 字节）；
  - 本机用量看板：token 热力图、首字延迟、速度，数据不出本机；
  - 升级流程：下载 → SHA-256 → 备份 → 原子替换 → 回读核对 → 热重载，任一步失败回滚。

## 6. OhWhale 里和我们相关的

- **语音通话链路**：QQ 来声 → WASAPI 环回 + VAD → 云端流式 ASR → 模型 → GPT-SoVITS → VB-CABLE → QQ 麦克风。我们以后做"她接 QQ 电话"时：
  - ASR 用本机的 SenseVoice（服务端已有），不把通话声音发云端；
  - 照它的"五段检查"做自检，验收必须"挂断重拨、不手动切设备也能听到回复"（它在第二台机器上踩过：QQ 新通话会把麦克风恢复成物理麦克风）；
  - "首段写入"不等于对方听到的延迟，分开量。
- **虚拟形象进 QQ 视频**：它用共享内存虚拟摄像头（CameraEmulator），自己也写了"带实体摄像头的笔记本上 QQ 仍显示实体镜头，没有根因"。我们暂不做。
- **表情包**：362 张、12 个情绪类别，建可迁移索引；我们 QQ 渠道发表情时可以照这个按情绪选（素材许可要单独核对）。
- **5 个 AstrBot 插件**（主动行为、群与空间操作、表情、语音选择、B 站）都跑在 AstrBot 进程里，和我们"AstrBot 只当转接头"相反，不用。

## 8. 工作台和 DSH 的差距：能力、权限、任务恢复（2026-10-28）

用户转来一篇 DSH 上手教程（模式、权限、计划 / 目标、繁忙时排队或插话、全局设定里的授权边界、插件和技能、IM 机器人、手机远程），评审里定了用法："提取工作台的能力边界、任务状态、权限与恢复机制，再与现有实现做差距表"。全文和逐条对照在知识库 `06 前端与工具/工作台与 DSH 的差距`。DSH 那边只按教程和截图整理，没跑 DSH 核对。结论：

- **最大的差距是任务和审批活不过重启**：工作台进行中的一轮和等批卡片（`wm/agent/core.py` 的 `Session.asks`）、自我改进任务（`Workbench.jobs`）、渠道申请卡片（`ChannelManager.drafts`）、QQ 电脑任务单（`ChannelManager.tasks`）都只在内存里。先做一种统一的落盘任务对象（编号、状态、阶段、心跳、绑定的审批），重启后恢复成"待核验 / 中断"，旧批复不套到新调用上。
- 能力上缺的目标模式、工作台排队 / 插话、QQ 任务先发计划、定时任务，都建在任务对象上，排在它后面。
- 权限上我们比 DSH 严（完全权限也守门、高风险每次问、审批上 QQ 不过期），要补"删除改成归档"和挂在任务上的"阶段授权"；自动审查最后做，只许把"问"降成"自动"、只限程序列好的低风险类别、不放宽守门。
