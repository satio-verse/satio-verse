# 小屋活动、实际饮用与执行回执：第六批

2026-10-31。已与工作台本轮修改联合发布，正式宿主与 8790 服务已核验。本批不把“源码存在”“动画脚本结束”“真实任务完成”“模型训练有效”混作一种验收。

## 本批修复

- 新屋活动表开放咖啡、手机、电脑、坐着转椅及杯中冷热观察。转换器 v5 是生成源，不能只手改生成后的场景 JSON。
- 明确的单项中文命令可直接进入现有技能，例如“冲咖啡”“玩手机”“使用电脑”“转一下电竞椅”“看看咖啡烫不烫”。这是有边界的命令路由；自由复合指令仍走原模型链，不是任意新动作生成模型。
- `room_do` 等待脚本与收尾的真实终态，最长 180 秒。排队、刚开始、失败或中断不能回复完成。状态不足、温度未知与动作失败原因保留。不存在的“翻倒椅子”不会被偷换成转向。
- 停止给活动独立取消标记，阻止后续拿取、冲泡、消费步骤，但允许在途动作结束和安全收尾。原生 UI 队列在真正下发前再次核对 pending 身份，已取消的旧回调不能重新启动活动。
- busy 失败和已完成请求保留近期 64 个 ID 的结果。它是有界去重，不是跨重启永久一次执行保证。

- 收尾失败暂停后续自动活动并清空待办，重新进入小屋后恢复；取消 A 收尾期间新排入的 B 也立即收到未开始的失败回执，不再等到 180 秒超时。

## 实际饮用与身体状态

消费回执只来自物理 `drink` 事件。准备时第一次实际接到咖啡扣一份豆；水分按真实入口毫升增加，咖啡的临时清醒有上限和衰减。空杯、洒在身上、仅播放动画均不补水。液体世界与待结算回执先保存，再原子保存 Needs 的效果和已处理序号；刷新和重放不会重复奖励。保证限定单个权威活动窗口。

V8 水分启用、饱腹继续暂停；当前只开放咖啡豆补货。有效精力参与原速度预算内的行走和非睡眠活动权重，不清空疲劳、对话负荷或真实 token 预算。极渴时不会再因精力充足而排除唯一可用的实际补水活动。

冷热以观察证据表达：看见冲泡是“可能烫”的推测，实际入口提供短时定性感受；看不见、证据过期或只有空杯则说未知。后台精确温度不发给角色。杯沿没有贴近嘴边时不再因等了两秒就强行倾杯；远离后回正。退手前等待杯子真正放平，尝到烫后停止继续喝下一口。

疾病、药品、食物消化和食物增益、厨房菜园、新动作网络训练未在本批实现。详细接口与研究边界见 [身体状态方案](embodied-life-state.md)。

咖啡 v3 的原始 run 保留 failed：其中刷新水分断言误拿尚未保存的自然衰减值和已保存记录比较。独立保存态复核确认水分、revision、完整消费账本与重载后相等；没有修改原始失败文件或把待保存衰减冒充重复奖励。进一步复测另列，不覆盖原记录。

v4、v5、v6 的 seed 13 入口均为 0，洒出分别约 0.462 / 0.452 / 0.480 ml，burn 均为 0；v5、v6 分别还有 6、8 次 hot 接触。hot 接触与造成 burn 的事件不同，不能写成完全没有热接触。v6 已等待接嘴最多 10 秒，预倾达到约 0.334 rad，杯沿仍离嘴 42–45 mm，未进入 35 mm 的接触门。

v7 仅作分层诊断：稳定阶段手腕在姿势求解后距目标中位 20.6 mm，ROM 再移约 19.6 mm，身体防穿层再推出约 72.9 mm；最后距目标约 90 mm。主要冲突在持杯几何与身体安全域，不能用无限积分、最后强制拉骨骼或放宽入口门槛解决。v7 同源分层诊断仍出现 1 次 burn（洒 2.332 ml）；诊断改变帧耗时，不能据此断言与 v6 的差异来自单一机制。v8 只启用现有精确 IK，姿势层残差从中位 20.6 mm 降到 1.20 mm，但身体约束仍推出手腕，0 入口、洒 0.893 ml。

最终 v9 仅对 V8 中手持的已登记非刚体杯启用该精确 IK，并把掌心朝身体的内转限制在 30° 内，使杯子位于腕与嘴之间。普通 sip、旧屋和其它姿势默认不变，后续 ROM、身体防穿、平滑仍执行，原 35/45 mm 接嘴门和 50/40 mm 回授限幅保留。空的登记杯也会启用该持杯姿态，不能称只在有液体时启用。显式复用旧 opts 的锁定恢复路径仍可能保留 opt-in 字段；普通切姿势不合并旧 opts。

v9 三种子各扣一份豆，消费、准备回执、保存与刷新重放检查通过，最终手空、无恢复错误。13 使用原相机；5/17 仅为截图换了侧前近景，动作/物理核心同 hash。连续调用尚未验收：当前活动每次都会再冲 6 秒，未先消费/拒绝已有余量；不能把 fresh-profile 三轮说成持续生活闭环。
