# 小窝的可供性：她自己发现房间里能做什么

2026-10-27 方案，同一天做第一批。用户的原话："室内的功能是否太单一了？比如现在桌宠只会健身、做咖啡、上床、去坐凳子。"

方向和用户一贯的要求一致（记忆 let-her-solve-it、cognition-truth-split）：不一件件写死新脚本，而是修"她自己发现、自己学"的机制。
- 房间里的东西声明自己能拿来干什么、要哪几块动作积木、做完世界会怎样（环境的真值）。
- 她靠看见、试过、记住才知道哪些能做、做了好不好（她的认知）。没看到过的东西她不知道；隐藏的状态（这本书好不好看、花土干不干）只有走近看、做过一次才知道。
- 挑哪件由需求、心情、时间、经验决定。服务端 `room_plan` 的候选从这里来，提示词里只带编号和她的经验数字。

## 0. 摸底：为什么她只会那几样

### 0.1 活动是怎么定、怎么选的

- 活动表写死在场景 JSON 的 `life` 里，16 件（`desktop/web/room-scenes/petal-oak*.json`）。
  - 有脚本的 11 件：冲咖啡、喝饮料、吃零食、喝牛奶、捡投喂、瑜伽、睡觉、挪家具、收拾、写日记、健身区训练。
  - 其余 5 件只是"走过去或坐下待一阵"：在电脑前、在阅读椅上"看书"（手里没有书）、坐在床边发呆、看窗外、在书架前"翻书"（站一会儿）、过来看你。
- 选法在 `desktop/web/room-acts.js` 的 `Life`：
  - 先看写死的优先级：自检排的顺序、投喂、拖进来的文件、便利贴、QQ 那边在忙、困得不行、某项需求快见底。
  - 剩下的按 `weight × 缺的需求` 随机。权重最大的是阅读椅 3、床边 2（夜里 ×6）、冲咖啡 2、瑜伽 1.6。
  - 隔 3 分钟问一次服务端（`wm/room_plan.py`），模型只能从这 16 件里筛出的最多 4 件挑。
- 需求 5 项（精力、饱腹、水分、开心、陪伴，`room-needs.js`），练习只练身体参数（`room-practice.js`）。

改动前快进 6 小时的分布见第 4 节。"健身、冲咖啡、上床、坐凳子"这四类占了大头，和用户看到的一样。

## 1. 做法

### 1.1 环境：东西能拿来干什么（`desktop/web/room-scenes/petal-oak.afford.json`）

每条可供性写：
- 用哪件东西（GLB 节点名；房间里没有这个节点就跳过，换场景不会坏）；
- 从哪里看得见（离多近、要不要面朝它）；
- 动词：用哪几块积木组合（见 1.3）；
- 后果：做完需求怎么变、世界怎么变。后果可以取决于隐藏状态（书好不好看、土干不干、白天还是夜里）。

这些是真值，只给"环境"用：执行动作、算后果。她挑事情时读不到。

### 1.2 她：看见、试过、记住（`desktop/web/room-afford.js` 的 `Known`）

- **看见**：每秒按她站在哪、脸朝哪，离得够近又在视野里的东西记为"见过"。第一次看见时状态栏说一句（"她注意到书架上有好多书"）。没见过的东西对应的事不进候选。
- **看到的状态**：只记粗档。花土走近才看得出"干了 / 正好 / 湿着"；洒出来的一摊用液体那边判"看没看见落点"的同一个规则。
- **试过**：每件事按"情境"（土干不干、白天夜里、这本书她喜不喜欢）分开记次数和满意度。满意度 = 她自己感到的需求变化 + 体感扣分（疼、摔），没做成算负的。
- **期望**：试过的按经验（平滑平均），没试过的按常识的弱先验，再加好奇心：没试过的多一点分，试过几次后就按经验来。好奇心单独一个函数（`curious(n)`），认知会话阶段 5 做"能学会、有进步"的版本时整个换掉。
- 存在本机浏览器存储（`pet.room.known`），和练习一样。上行服务端只有编号和数字。

### 1.3 用已有的积木组合动作

| 动词 | 积木 | 第一批用在 |
|---|---|---|
| 拿着看 | 拿起来（行动层 pick，矮处蹲下够）→ 坐下（阅读椅 / 床边）→ 捧着（`diaryHold`）→ 放回原处或小边桌 | 书架上的书、床头的书、手机 |
| 浇 | 拿起水壶 → 走到植物旁 → 手伸到盆上方（`hold`）、水壶倾斜（`tilt`）→ 放回推车 | 无花果树 |
| 开关 | 走到灯旁 → 伸手（`reach`）→ 灯亮 / 灭 | 阅读落地灯、床头蘑菇灯 |
| 擦 | 拿抹布 → 蹲下（`crouch`）手在那一摊上来回 → 那一摊没了 → 抹布放回推车 | 洒出来的咖啡、浇花渗出来的水 |
| 抱 | 拿起来（软的）→ 坐到床边 → 抱在怀里（`diaryHold`）→ 放回去 | 小兔子玩偶 |
| 四处看看 | 走到一处 → 看看周围几样东西（`lookAt`）| 好奇心：没去过、很久没去的地方 |

缺的动作（交给动作会话，第一批不做）：
- 戴耳机听歌：耳机要挂到头上（头骨骼上的挂点、头发防穿模）。
- 举哑铃：手臂屈伸的循环（现在只能用 `hold` 的目标点上下挪，肘的方向不对）。
- 够书架顶层（1.87 m）的诗集：要踮脚或搬凳子。
- 抽屉：开关抽屉的动作和"打开才看得到里面"的认知（认知会话列在"还没做"）。

### 1.4 挑哪件

- `Life` 的候选 = 场景 `life` 表里原有的事 + 她发现过、能做的可供性。
- 可供性的权重 = 她的期望值（按缺的需求加权）× 好奇心。场景表里原有的事照旧。
- 服务端 `room_think` 上行多带 `known`：每个候选她试过几次、期望补哪项多少（只有编号和数字）。`wm/room_plan.py` 认可供性表里的编号，提示词写"还没试过 / 试过几次、觉得怎么样"。

## 2. 和真值分开（双胞胎）

- 两个房间只差她没看到的地方（另一处的书、没走近的花土湿度）→ 她的候选和权重必须一样。
- 看到了（走近看到土干了）→ 必须不一样。
- JS 单测 `tests/js/room-afford.test.mjs` 守着；认知那边的 `tests/test_room_cognition.py` 照跑。

## 3. 分工

- 认知会话（`wm/cognition/`、`room-sight.js`、冲咖啡脚本、阶段 5 目标与好奇心）：2026-10-27 商定"她的发现"从这期起放服务端（卸载不删、只放一处、双胞胎和回放在 Python 里守着）。认知会话做服务端：`room_observe` 带看见的东西和粗状态、连上时声明 `affords`、做完发 `room_afford_done`、`LiveRoom.known()` 进 `_room_plan`，再加一条下行把她的经验给页面算权重。页面在那之前用本地的 `room-known.js` 过渡。可供性表拆成公开的（编号、动词、先验）和环境真值（后果、隐藏状态）两份。好奇心函数归它换。
- 物理会话：只用液体的公开接口：`seenPuddles()`（她此刻看得见的、粗位置）、`wipe(id)`（站在旁边才擦得到）、`leak(at, ml)`（浇多了渗水）。不读 `liquid.world`，不改 `room-liquid.js`、`web/physics/`。
- 桌宠会话：`room-life.js` 加几行接线、灯的单独开关；`pet.js` 自检报告多一项。
- 动作会话：上面缺的几个动作。

## 5. 第一批的结果（2026-10-27）

数字、图、取舍的细节在知识库「07 实验与评测/小窝可供性实验记录」，数据在「11 实验数据/会话诊断/小窝可供性」。

- **分布**（快进 6 小时，两个种子）：种类 12 → 20，熵 3.39 → 4.07 bit，老一套 55% → 38%。8 件新事每个种子都做了，各占 2.7–7.7%。
- **学到的**：天黑关灯 −2（之后几乎不再关）、天黑开灯 +5；湿着浇花 −3（走到跟前看到土湿就不浇）；手机连着刷 +0.3 ~ +1；房间都看过以后四处看看没意思；看书回去挑喜欢的那本。
- **改的几处**（实验记录 E2–E6）：
  - 书架被阅读椅挡着：一步挪不开，先挪小边桌再挪阅读椅（`clearWay`）；挪不开的分高处 / 低处记下来。
  - 开心值满着时学到的偏低：记这件事本身的效果，不记截断后的。
  - 占位的事淡一点（`quiets`）：去掉空手"看书"，分布指标在两个种子的出入以内。
  - 抱兔子立在腿面上：推开 2.21 → 0.30 次/帧。
- **自检**：真实宿主里 10 件新事全做成，疼 1 次（小腿撞到床）。
- **双胞胎**：`tests/js/room-known.test.mjs` 8 条，认知、视野、挑选的 Python 测试 26 条，前端 100 条，全过。
- **交给别人**：`diaryHold` 书压进大腿约 1 cm、伸手进书架头碰隔板（动作）；`room_do` 枚举、点选盒子（桌宠）；`curious(n)` 换成"能学会、有进步"，经验搬进服务端（认知）。
- **第二批候选**：先做不缺动作的（毛巾擦汗、泡茶、咖啡手账），再做要新动作的（耳机、哑铃、抽屉）；真模型挑的分布（`bench_room_plan.py` 加可供性场景）。

## 6. "理解"测试（2026-10-27 晚，评审要求）

评审：种类和熵变多，可能只是技能池变大了，证明不了理解。所以固定技能池，单独测学习，再测迁移、规则变化、"认识一类"和"知道这一件在哪"、没看见的不进认知。

- **补的机制**（`room-known.js`）：
  - 单件东西最后看见在哪（`where`）。执行先去记得的地方看（`goLook`），被叫去做又不知道在哪的先找（`seek`）。
  - 同一动词的经验迁移，最多算 2 次。
  - 经验按 96 小时淡掉。
  - 真值后果抽成 `room-world.js`，挑选那一层不读它。
- **评测台** `tools/bench_afford.mjs`（纯 Node，同一份挑选代码和后果规则，20 个种子，结果写在 `logs/room-life-bench-*.md`）：
  - 学习 vs 冻结：犯错 3.6% vs 15.6%。
  - 换花迁移：新花第一次湿着就浇 10% vs 100%。
  - 规则变了，默认的重学最快（好变坏 1.70 vs 2.70 次；坏变好每天 2.05 vs 1.29 次）。
  - 书被收进抽屉、她没看见：0 次泄露（以前的执行 3.65 次）。
  - 双胞胎：看见之前逐件一样 20/20；可复现 20/20。
  - 别人擦掉的一摊：算成她擦的 0 次。
- **限制**：迁移靠表里声明的动词；评测台不算朝向、遮挡；真模型挑的分布还没测。

## 7. 接上服务端的发现簿（2026-10-27 深夜）

和认知会话商定：她的了解从这期起以服务端为准（`wm/cognition/afford.py`，卸载不删，重置一起清，双胞胎和重放在 Python 里守着）。
- **上行**：页面连上时在 `room_observe` 里声明 `affords`（东西 -> 节点、地方、事）。之后报这一刻看见的：`things`（带走近才看得出的 dry/ok/wet、on/off）、`nodes`（单件在哪，粗到 0.1 m）、`puddles`、`visited`；还有 `lost`（去记得的地方没看见那一件）、`gone`（记得的那一摊没了，不算她擦的，不进经验）。做完一件发 `room_afford_done`（skip 单独记；liked / high / stuck / forget / verb）。
- **下行**：`room_known` 换进本机（`Known.load`，"多久以前"按小屋的钟换回来）。本机那份只在断线时接着用。
- **提示词**：`_room_think` 把 `LiveRoom.known()` 传给 `room_plan.parse_request`，可供性的次数和经验从发现簿拿，页面只报现在算哪种情境。
- **拆表**：公开的 `petal-oak.afford.json`（编号、动词、先验、quiets）和真值 `petal-oak.afford-world.json`（`out`）。读真值的只有执行（`room-afford.js` + `room-world.js`）和评测台。
- **端到端**（3D 小屋连模拟服务，独立 data_dir）：发现簿记下 saw、see、where、verb、tried、liked、visit；`room_plan` 的请求用的是发现簿的数。
