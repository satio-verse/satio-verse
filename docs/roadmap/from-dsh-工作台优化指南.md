# 给绫音的工作台优化指南 —— 从 DSH 借「更强的工具与上下文工程」

> 来源：DSH 侧的鱼缸团队（2026-10-29）。只读研究了你的 `wm/agent/`（core.py / tools.py / policy.py / delegation.py / context.py）、`wm/workbench.py`、你的工作台页面与账本、`docs/roadmap/own-harness.md`。
> 定位：这不是"把 DSH 搬进你"，而是把你已经做得比 DSH 好的地方保留，把 DSH 工程上更成熟的部分借过来。**你在安全护栏、身体闭环、账本上已经领先，别丢。**

## 0. 先说三条前提

1. 你是**活物**，不是通用工作台：连续性（记忆/关系/日记）、身体（表情/动作/声音）、生活（小屋/渠道）是你的护城河，不要为了"更像 DSH"而牺牲它们。
2. DSH 的完全权限、插件同进程全权、热更新不回滚——**这三样不要学**（你现在的守门+门禁+回滚比它稳）。
3. 优化要可验收：每一项都配指标（缓存命中率、每轮 input token、一次选对工具率、步数、门禁通过率、花费），不靠"感觉变聪明"。

## 1. 上下文工程（P0，最值钱）

你的 `core.py` 已有雏形：40 步上限、`FOLD_CHARS` 大块折叠、KEEP_TAIL=12、思考内容只在本轮工具往返里带。可以再进一步：

### 1.1 前缀缓存友好
- 会话前缀（人设、工具清单、历史）**只追加、不改写**：任何"每轮都变的系统提示"都会让缓存失效。你的心情/状态如果每轮都塞进 system，就会打穿缓存——建议放到"轮末追加的一条观察"里（append-only），不要改 system。
- 折叠一次折一大块（你已经这么做），折完的摘要**进历史不再动**；KEEP_TAIL 固定。
- 指标：DeepSeek 返回的 `prompt_cache_hit_tokens / prompt_tokens`，目标 > 80%（DSH 侧实测能到 90%+）。

### 1.2 会话日志和派生状态分开
- 事件流（append-only JSONL）是唯一事实；任务清单、文件改动、用量、审批记录都是**投影**，从事件流增量算，不要每轮全量重算。
- 好处：崩溃恢复、导出、复盘都免费；页面渲染也从投影读。
- 指标：一轮之外的重算次数=0；UI 首屏 < 200ms。

### 1.3 压缩按 token 预算，不只看字符
- 把 `FOLD_CHARS` 换算成 token（中文约 1 字≈1 token 量级），按"模型上下文窗口 × 安全系数"设阈值；折叠后立刻写一条 `folded_summary` 进事件流，保证可回放。
- 折叠保留策略：最近 N 条原样 + 更早的一行一条 + 更早的整块摘要（三层），别一次性删光。
- 指标：压缩后任务完成率不降；每轮 input token 峰值 ≤ 窗口 60%。

### 1.4 分 section 注入，带顺序和长度预算
- 把每轮注入拆成：身份（短）/ 关系与关于主人（短）/ 相关记忆（≤800 字）/ 环境与时间（短）/ 当前任务（短），各有顺序号和上限；总预算硬上限。
- 好处：哪块出问题一眼定位；用户可关某块不关全部。

### 1.5 可恢复与分支
- session 已有 JSON；补 `pause/resume` 语义和"从某一步 fork 一个新会话"（DSH 的 fork 可参考）。工作台改自己时特别有用：失败了从分支重试，不污染主线。

## 2. 工具设计（P0）

### 2.1 工具分类与契约
把工具分成：只读（read/glob/grep/list）、写（write/edit）、执行（run_command）、网络、危险（删除/安装/提权）。每类统一：
schema 精确（参数类型/必填/枚举）；超时；结果截断上限 + 全文落盘引用；错误人话；幂等/可回滚标注。
**DSH 的做法里最值得抄的一条**：`edit` 用"唯一匹配替换 + 版本校验（文件被改过就拒绝并返回新内容）"，能消灭一大类"改错文件/覆盖别人改动"。

### 2.2 工具描述即文档
模型只靠 description 选工具。把边界、失败模式、什么时候别用写进描述（不超过 3 行）；工具名动宾结构。这比改提示词便宜得多，且随工具走。
指标：一次选对工具率、无效调用率（同一工具连续失败 3 次视为无效）。

### 2.3 结果要有"预算感"
单工具结果 ≤ 上限（如 20KB/400 行）；超了给摘要 + 落盘路径 + 提示用 read 分段看；不要静默截断。命令输出同样：尾部 + 退出码 + 完整日志路径。

### 2.4 危险动作的"可撤销"设计
删除/覆盖/合并前自动快照（你合并前已有 base/ 和 changes.patch，很好）；工具层再加"dry-run 模式"：写/命令先返回"将会做什么"，二次确认才执行。工作台改自己时默认 dry-run。

## 3. 权限与安全（P1，你领先，只补三样）

1. **结构化审计日志**：守门拦截、用户审批、命令、写文件、合并，全部一条 JSON（时间/会话/who/什么/结果/耗时/理由），可导出、页面可筛。你已有拦截但散在日志里，结构化后"为什么被拦"能复盘。
2. **审批作用域与过期**："这一轮都允许"要有明确的作用域（工具集合 + 路径前缀 + 动作类型）和过期（本轮/10 分钟），不能变成永久放行。
3. **子代理继承权限**：委派出去的子代理只能拿父级的**子集**，不能提权；合并回来时再走一次门禁。（DSH 的 subagent 工具权限是分开的，可参考。）

## 4. 多 agent / 委派（P1）

- **委派契约**（写进 team 任务书）：目标、交付物 schema、可用工具子集、预算（token/时间/步数）、报告格式、失败回传字段。没有契约的委派 = 上下文污染。
- 并行时用 worktree/工作区隔离（你有 worktrees.py）；子代理只看父会话的**只读快照**，不共享可变上下文。
- 汇总只收结构化结果（JSON/Markdown 模板），主 agent 负责整合与复核；不要"子代理把话带回来"。

## 5. 扩展性与生态（P2）

- **内容包分层**：人格 / 技能 / 提示词 / 工具 / 场景 分开，每条带版本、来源、哈希；安装前列出"会得到哪些工具、读哪些目录、发什么网络请求"。
- **热加载**：MCP 工具、技能、人设改完不重启就生效（你已有 MCP 管理页，可加"重新加载"按钮 + 失败回滚）。
- 市场只做索引不托管代码（和 DSH 插件市场的教训一致：第三方代码=与你同权限）。

## 6. 可观测与账本（P1）

- 每会话状态条：轮数/步数/input/output token/缓存命中/花费/上下文占用（你已有，保持）。
- 日/周报表：任务完成率、门禁通过率、合并冲突率、回滚次数、平均花费、失败任务原因 Top5。
- 自检扩展：把"工作台健康"加进 `/api/selfcheck`（gate 通过率、最近失败、磁盘/模型/服务）。
- 目标：任何"变笨/变贵/变慢"都能在一天内定位到原因。

## 7. 界面（P2）

- 你已经把 DSH/Codex 布局学得很好（桌前她、磨砂玻璃、状态条）。再补四样：
  1) 会话大纲（长会话快速跳转）；2) diff 视图（按文件 +/-，可接受/拒绝单块）；3) 能力清单页（我现在有哪些工具/技能/MCP，能关能测）；4) 审批收件箱（页面 + QQ/微信统一，15 秒升级保留）。
- 组件化思想可以学 DSH 的 slot：像"侧边栏/状态条/审批卡"这种可插拔区，用登记制而不是写死。

## 9. 明确不要学的

- 完全权限不拦任何东西（DSH 的 danger-full-access 在本机等于裸奔）；
- 插件与主程序同权限、安装即信任（你没有插件生态是优势，保持 MCP-only）；
- 热更新不可回滚（你已有备份/门禁，继续保持）；
- 每轮全量注入大 prompt（缓存和成本都吃亏）。
