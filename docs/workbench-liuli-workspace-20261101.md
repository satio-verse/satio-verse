# 工作台文件、网页与共享外观更新

本轮针对工具区可用性、浏览器空白反馈、整窗缩放和共享外观。没有将整个桌宠产品或所有插件标记为已完善。

## 交付

- 工具栏保留文件、浏览器、终端、协作任务；其他功能放入带文字的更多菜单，当前工具有独立选中标记。
- 文件区采用两行头部、多文档标签、面包屑、目录树和按需查找，支持 Markdown/源码、目录分页与错误反馈。关闭工具区保留本会话文档。
- 全文和正文选段可加入真实会话材料库，保存文字快照及来源路径。网页选区保存 URL、标题和原会话身份；迟到结果不会加入另一会话。加入材料不自动发送。
- 网页使用真正独立的 WebView2 标签，分别保留页面状态、历史及缩放。提供紧凑地址栏、开始页、收藏、最近浏览和实际可用的菜单。
- 加载超过 10 秒提示网站资源较慢，允许继续等待、重试或使用系统浏览器。本机 Bilibili 复现为正文生成前等待 CDN 阻塞脚本，随后能正常渲染；没有宣称外站加载问题已彻底消除。
- 主界面 WebView 固定 100%，禁止浏览器缩放与捏合；Windows DPI 保持生效。界面字体由设置调整，网页可单独缩放。
- 外观共享柔雾玻璃/纯色、本地壁纸与取色、字体、模糊及不透明度。正文维持可读表面，桌宠背景保持透明，支持减少动效。

## 实际修复

1. 晚到的宿主能力握手会将未主动选择文字阅读的标签升级为原生网页，取消旧阅读请求。
2. 地址栏聚焦时，从其他入口显式打开网页、切换或新建标签都会同步地址；异步回包不覆盖正在编辑的网址。
3. browser-data 被同名文件占用时即时报告初始化失败；主文档 HTTP 错误回传到界面。
4. 去除重复文件/浏览器头部，区分工具悬停与选中态，减少消息叠加外边距。
5. 旧宿主仅提供单网页时，隐藏多标签操作并禁用尚不支持的选区/缩放；保存的其他标签保留，升级后恢复。新版拒收缺少标签身份的网页回包，防止串页。

## Lexora 借鉴

本轮接入“选中材料 → 文字快照和来源 → 指定对话草稿”。未复制 Lexora 或 Liuli 源码，也不宣称能直接加载其框架插件。下一阶段按以下依赖顺序推进：

1. 引用增加返回来源位置：Markdown 行段、PDF 页码、网页定位。当前只有快照及路径/URL。
2. 文档统一 documentId/revision/dirty/recovery/saveAs，写入核对版本，编辑、保存原件和导出分别回执。
3. Office 作为可下载组件接入真实 read/edit/render/export，分别验证格式保真；当前 Markdown 预览不是 Office 编辑器。
4. 已有 TeamManager/worktree 增加持久化邮箱、幂等补充消息与结构化成果（产物、证据、未解决问题、复核状态）。

参考：[Lexora 引用机制](https://github.com/useLexora/Lexora/blob/master/apps/buddy/service/resources/skills/plugin-creator/references/references.md)、[委派实现](https://github.com/useLexora/Lexora/blob/master/apps/buddy/service/src/agent/execution/ExecutionDelegationService.ts)、[Office 组件](https://github.com/useLexora/plugins/blob/main/plugins/office/README.md)、[Liuli](https://github.com/LilycleHeart/qqnt-liuli-theme)、[DSH Liuli](https://github.com/LilycleHeart/dsh-liuli-ui-enhance)。

## 启动及边界

在 `G:/RunProgram/WorldModel_v1/desktop` 双击 `start-pet.cmd`，再从托盘打开工作台。直接打开 `web/workbench.html` 缺少原生宿主。普通浏览器访问工作台时提供文字阅读及系统浏览器出口。

玻璃是应用内分层材质，不是 Win32 桌面透景；取色为独立简化算法，不是完整 MCU/M3。网页设备权限、自动下载、Office 原格式编辑不属于本轮完成范围。
