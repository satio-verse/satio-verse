# 工作台与常驻搭档基础更新 · 2026-10-31

本轮直接在绫音最近修改后的工程上审查、补充，没有恢复到旧版快照。目标是让现有桌宠逐步成为能持续交付成果、过程可检查的个人搭档，同时明确本机服务与未来手机、云端的边界。

工作台右侧工具入口现在按「会话能力 / 全局服务 / 待接入能力」展示，可以搜索、折叠、查看工具参数及来源、预览不同 Agent 预设。预览预设不会改动当前会话。

新增自动读取当前工作区根目录的 AGENTS.md / CLAUDE.md；遵守读取权限、黑名单和路径边界。子目录约定仍需按任务读取。没有把附件里的文字当作开发指令执行。

### 持续任务

入口：工作台右侧「Agent 与嵌套任务 → 持续任务」。输入明确目标，可选开始时间和整个目标的预算。任务使用当前工作区、权限、预设、模型与材料，建立独立会话；当前对话可以继续使用。

- 工作台窗口关闭后，本机服务仍可推进任务。
- 进展、等待用户、阻塞和完成状态保存到 SQLite，提供事件游标。
- 可以暂停、继续、查看会话或手动标记完成。暂停不会被模型的旧回报覆盖。
- 总预算累计所有轮次及子代理费用；0 表示不额外设置目标额度，现有账本规则仍生效。
- 服务退出时，运行中的任务标记为需要核对。重启不会盲目重放结果未知的操作。
- 同一数据目录只允许一个调度器接管，防止双开重复执行。
- 提醒写入工作台通知与未读状态；测试没有发送真实 QQ 或社交消息。

这是本机常驻执行基础。电脑关闭或桌宠服务退出后不会继续运算。OpenAI 官方 dots 文档描述的是另有云端电脑的常驻智能体，两者部署条件不同：[官方说明](https://learn.chatgpt.com/docs/dots)。普通聊天不会被静默转成持续任务。

已有提醒扩展的 schedule_due 仍是按调用检查到期；已有目标扩展仍是全局目标记录。新调度器没有偷偷消费旧提醒，也没有把旧目标自动当成执行授权。

### SnowLuma 随桌宠启动

新增设置：「外部渠道 → 连接与模型 → 随桌宠启动」。启用 QQ 且填写完整 SnowLuma 安装目录后，桌宠会启动已安装的 SnowLuma，使用其自带 Node，隐藏终端，复用已有进程，提供失败退避和独立启动状态。

它不再只尝试连接一个尚未启动的 OneBot 服务。关闭桌宠或取消自动启动不会杀掉用户手动启动的 QQ / SnowLuma。

仍需区分服务启动与账号挂接：本机 hookAutoLoad=false，QQ 本身重启后仍可能需要在 SnowLuma 挂接。精确按账号挂接需要 WebUI 授权接口；没有改成无差别挂接所有 QQ。首次安装、登录及第三方条款也未自动代办。详见 [启动说明](snowluma-startup-20261031.md)。

## 本轮修复的底层问题

1. **附件同源内容执行风险**：原图片接口可能返回非图片内容。改为检查真实位图格式，并沿用路径、大小及内容摘要验证，返回 sandbox / nosniff 等响应头。
2. **直通扩展绕过通用约束**：直通 MCP 调用现在经过与正常 MCP 一致的连接、调用、具体工具及启动命令黑名单检查。
3. **工具名覆盖与过期快照**：拒绝覆盖内置工具名、歧义重复名和失效版本，避免调用另一个同名工具。
4. **后台命令 PID 复用**：workbench-jobs 改用 PID、创建时间及启动命令核对身份；停止时保留进程句柄。旧任务缺少身份时不再只凭 PID 杀进程。
5. **后台命令状态竞争及大日志**：跨 MCP 进程事务锁、原子落盘、损坏记录拒绝覆盖；日志有界读取并支持向前翻页。
6. **试启动碰触正式持续任务**：代码更新的 mock 试启动使用独立 agent.home 并关闭持续任务调度，避免抢正式任务或产生真实副作用。

这是一轮有针对性的审查和修复，不代表已经证明整个系统不存在漏洞。完全权限仍使用用户现有授权；本轮没有修改全局权限、黑名单或替用户开启数据上传。

## 手机端之前应该怎样优化底层

目前最需要的是分离运行服务、任务状态和显示终端。手机、桌宠窗口与工作台应连接同一个任务服务，而不是各自复制一个无法同步的 agent 循环。

建议按以下顺序推进：

1. **设备配对与认证**：增加可撤销的设备令牌、会话绑定、TLS 和设备列表。现有 8790 的 Host / Origin 检查属于本机浏览器边界，不是远程身份认证，不能直接作为公网手机 API。
2. **稳定任务与事件协议**：把会话、持续目标、产物、审批、通知采用统一版本化 API；移动端通过事件游标断线续接，重复请求使用幂等键。当前持续任务的事务状态与事件游标是这一步的起点。
3. **执行器与模型分离**：任务调度选择本机或远端 worker。文件路径与命令属于设备能力；手机只提交目标、看进度、提供材料和决策，不能把手机路径误当成桌面路径。
4. **材料与凭据管理**：附件使用独立 blob 标识和访问授权；密钥保留在服务端或设备凭据库，手机不复制桌面环境变量。任务同步的是引用和状态，不是整个用户目录。
5. **真正离线后的续行与推送**：有公网服务器后部署常驻 worker 和推送；显式说明哪些任务仍需本机在线。先完成配对和可撤销连接，再接管手机通知。
6. **上下文质量**：统一全量事件记录与模型投影；增加摘要质量验收、检索索引、来源引用和预算追踪。先保持原始记录可回查，再优化压缩，不能用删掉关键过程来换低 token。

这轮没有发布手机应用、远程访问接口或云端执行。既有插件社区、数据贡献接收端和更新下载的可部署版本仍见 [部署说明](platform-publishing.md)；没有公网服务时保持本地验证，不伪装社区已上线。
