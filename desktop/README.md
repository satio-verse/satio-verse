# desktop/: 桌宠 (2D+3D 桌面陪伴)

路线和决策见 [docs/roadmap/desktop-pet.md](../docs/roadmap/desktop-pet.md). 这里放桌宠的全部代码, 不改 `wm/`、`web/`、`tools/`、`config/`.
桌宠只是现有服务的一个新客户端: 页面和服务同源, 复用 `web/` 的模块, 阶段一的改进通过同一个服务自动用上.

## 现在到哪了: M0 完成, M1 基本完成, M2 的本机接口 (OpenAI 兼容 API + MCP 服务端) 和操作面板 (人设预设、云端模型、MCP 客户端、skill) 做完了; 人设和工具调用等服务端支持

- **宿主** `host/` (C++17, Win32 + WebView2):
  - 透明、置顶 (可以关)、不进任务栏的无边框窗口;
  - 按角色像素点穿: 页面发命中掩码, 宿主 30 Hz 查光标, 切 `WS_EX_TRANSPARENT`;
  - 拖动 (按住角色, 或者侧菜单最上面的十字箭头把手; 小屋模式还可以按住卡片顶上的标题), **松手就停在那里** (2026-10-24 用户说没法把桌宠放到想放的位置: 原来松手总要掉到地面):
    - 脚离下面最近的地面 (露在外面的窗口顶边, 没有就是任务栏顶边) 不到 28 像素才吸上去; 拖进任务栏里松手就站回任务栏上. 窗口左右至少留三分之一在屏幕里.
    - 站在窗口上时跟着窗口走, 窗口没了就往下掉 (`ledge.cpp`); 停在半空的不趴.
    - 托盘里打开"松手落到地面"是原来的样子 (松手就往下掉). 位置记在设置里 (`pet.pos`), 下次启动放回原处.
    - 趴着时按住要移动 5 像素才开始拖; 按着的时候宿主不再中途切成点穿 (光标滑出剪影, 页面就收不到移动, 拖不起来);
  - 托盘: 说话、设置、小屋模式、看你在做什么、显示/隐藏、静音、暂停渲染、空闲帧率、置顶、眼睛跟着鼠标、趴着、松手落到地面、本机接口开关、暂停 QQ、重新加载、退出;
  - 全屏程序、游戏、演示时自动隐身;
  - 页面就绪后把 WebView2 的内存目标设成"低";
  - 本机接口 (M2, 默认关): OpenAI 兼容 API 和 MCP 服务端, 见下面"本机接口";
  - 自检模式 (`--selftest`).
- **页面** `web/`:
  - `pet.js`: 主循环、帧率、命中掩码、气泡和输入框.
  - `avatar-lean.js`: 省内存地加载 VRM. 变形纹理按图元压缩、去变形法线、贴图 512、上传后释放原图.
  - `desk-body.js`: StayStill 待机. 用 `web/locomotion.js` 的行动层和一个空的"桌面场景", 手势叠加在待机上.
  - `talk.js`: 连服务的 `/ws`, 协议和网页一样.
  - `api-bridge.js`: 本机接口转来的请求变成 `/ws` 上的一轮对话或本地动作, 结果报回宿主.
- **页面地址**是 `<服务>/pet/pet.html`: 宿主拦截 `/pet/*`, 从 `desktop/web/` 读文件返回; 其他路径 (`/static`、`/api`、`/avatars`、`/ws`) 照常走服务. 服务端不用改.
- **灵动对话栏** (左下方, 盖在腿上, 不挡脸; `web/ui-shell.js`): 平时收起, 随对话变形, 从下往上长.
  - 在听: 音柱跟着音量跳, 下面是识别中的文字;
  - 在想: 头的左边冒出一个思考气泡 (三个跳动的点, 两个小圆圈连向脸), 对话栏里只留你说的话;
  - 在说: 占满左下方那一栏, 逐字出现, 长回复自动滚到最新;
  - 说完停 6 秒收起;
  - 点它展开最近 8 轮对话和输入框 (展开后顶到胸口下面, 脸还露着).
  - 麦克风开着时, 对话栏的位置一直留一个小红点.
  - 工具确认卡片叠在对话栏上面.
  - 原来在头顶, 说长话和展开记录时会挡住脸 (用户提的), 2026-10-24 挪到左下方.
- **趴着** (`desk-body.js` 的 leaner, 2D 在 `live2d-avatar.js`): 站在任务栏 (或窗口顶边) 上放着不动 15 秒, 她就把它当栏杆趴上去. 不挡你的屏幕, 也更像真的在那儿.
  - 3D: 上身往前压、两条前臂叠放在栏杆上 (左手搭右肘、右手搭左肘), 头抬起来看着你. 宿主把窗口往下挪, 让前臂底下那条线正好落在任务栏顶边; 线以下裁掉 (画布的 clip-path), 掩码也不算, 下面的任务栏照常能点.
  - 2D (Eustia 的手是一张交握的图, 叠不了胳膊): 从任务栏后面探出头和肩膀, 往前探、歪着头.
  - 趴下的过程中, 栏杆线从脚底慢慢升到前臂, 窗口跟着往下挪: 看起来是她一边往前趴、一边沉到任务栏后面.
  - 趴着时点她一下 (没拖动): 依次歪头笑、点头、抬起右手招一招 (2D 是歪头)、害羞地瞟开; 按住拖动就站起来, 落地后重新计时.
  - 眼睛照样跟着鼠标, 也能照常说话 (说话的手势不叠到胳膊上, 头部动作照常). 对话栏挪到头顶上方的空处, 侧菜单挪到栏杆线以上.
  - 尺寸按每个角色的手臂长度算 (miomio 上臂加前臂 0.42 m, wendy 0.33 m; 按同样米数 wendy 够不着, 胳膊会伸直指向镜头).
  - 趴好之后栏杆只慢慢跟着肩膀走 (时间常数 4 秒): 每帧跟着肩膀算的话, 待机换重心、歪头时栏杆线会晃, 宿主跟着挪窗口, 整个人一跳一跳的.
  - 托盘里可以关 ("放着不动 15 秒后趴在任务栏上", 记在设置里 `pet.lean`). 3D 没挂上行动层的角色做不了, 托盘里这一项会变灰.
- **侧菜单** (右侧): 光标移到角色身上时滑出, 移开 1.5 秒后收起. 按钮: 麦克风开关 (开着时发红光)、打字、人设预设、小屋模式 (小房子, 见下面"小屋", 再点一下回到桌面)、静音、置顶 (图钉)、设置、隐藏, 和托盘是同一套开关.
  - 人设预设按钮点开是一个小列表 (当前的打勾, 标着本地还是云端), 点一个就换过去, 对话栏提示"换成「…」了"; 最后一项"管理预设…"打开设置窗口. 设置窗口开着的话会跟着刷新.
  - **置顶** (图钉): 默认置顶 (蓝色图钉). 点一下取消, 图钉划掉, 对话栏提示"不置顶了": 之后和普通窗口一样, 点别的窗口就会盖住她.
    - 不置顶时, 拖动她、打开输入框会把她提到普通窗口的最上面; 被盖住的地方不算"光标在她身上", 侧菜单不会在别人的窗口后面滑出.
    - 记在设置里 (`pet.topmost`), 下次启动照用. 设置窗口保存时不会把它改回去.
- **眼睛跟着鼠标** (托盘里可以关, 记在设置里 `pet.follow_mouse`): 宿主把光标相对桌宠窗口的位置发给页面, 光标动过之后 3 秒内她看着光标, 之后回来看着你.
  - 角度按光标离她的头多远算 (假定人离屏幕 600 个 CSS 像素). 2D 眼睛快、头慢, 头最多转 14°.
  - 3D 用表情引擎的视线. 引擎把模型的眼球范围改成了左右 30°、上下 25°, 动漫眼眶装不下: 光标一到屏幕边上, 虹膜和瞳孔转到眼角, 只剩眼白 (用户发现的).
    现在眼球最多转左右 10°、上下 9° (miomio、wendy 文件里写的就是 10°), 超过 6° 的那部分由头转过去分担一半 (最多左右 24°、上下 12°); 小屋里头归行动层管, 只转眼睛.
    `gaze=1` 自检报眼球和头的角度: 光标在右边很远时眼球 10°、头约 23°.
  - 光标在她头附近 (500 像素内) 移动时升到 30 帧, 远处的照空闲帧率跟, 不额外耗电.
  - 光标位置只在宿主和本机的页面之间传, 不发给服务端.
- **说话**: 双击角色、侧菜单的键盘按钮或托盘"说话…"都能打开输入框, 回车发送. 声音、口型、表情、手势跟网页版一样. 说话时页面升到 30 帧.
  - 桌面上没有房间, 能力声明里不报走动、坐下、拿放、抬腿, 服务端会把这类要求改判成"做不到".
  - 连上服务端时上报 `state.place: "desktop"`: 服务端换成桌宠的提示词, 不会说"我去坐沙发"; 问"你在哪"答"在你的电脑桌面上".
  - **蹲下** (`squat`, "蹲下来""半蹲一下"): 程序动作和 StayStill 都没有这个姿势, `desk-body.js` 叠上去.
    - 做法: 髋部压低、略往后, 上身前倾、头抬回来看着用户; 两腿用行动层的 IK 把脚钉在原地; 蹲一会儿自己站起来.
    - 膝盖并拢、双手搭在膝盖上: 穿短裙的模型正对镜头蹲, 两膝分开会走光, 第一版连拍时看到了, 已改.
    - 只有挂了 StayStill 的身体才在能力声明里报 `squat`.
- **待机** (`web/desk-body.js`):
  - StayStill 只留左右换重心. 摸脸、挠头、挠胳膊、看表、伸懒腰和环顾会穿模或像乱动, 去掉了.
  - 双手交叠在身前或抱臂、真压进衣服的待机片段, 播 3 秒就自动换掉, 换掉的按模型记在本机 (localStorage 的 `pet-idle-avoid-v5:<模型名>`).
    - 一帧算"压着"要两条都满足: 两只手都在身前, 而且这一帧接触层真把手臂推出身体 5 mm 以上 (`stats.lastPush`). 只看位置会把动捕自己两手合在腹前、
      没插进衣服的段也去掉 (silvercat 的 idle_08, 最平静的一段); 只看推开次数又会误伤手垂在大腿边的段. 裙子那一项不算 (手放在腹前本来就贴着裙子).
    - 行动层自己让手在腰前交叠 (`layer.claspW`) 和做表情动作 (比心、拍手、托腮…, `layer.emoteUses`) 时不算, 否则几分钟就只剩最少的几段.
    - 键 2026-10-26 从 v2 换到 v3、2026-10-27 换到 v5 (v4 只在开发版里试过), 旧键里误去掉的段不带过来. 动作自检报告里的 `avoided` 应该是空的 (silvercat 实测两次都是空的, 12 段都在).
  - 手势叠加在待机上, 包括鞠躬的弯腰和思考时的歪头. 做手势时肩膀回到标准位置, 手臂才不会横过脸.

## 构建

用 CPEditor 自带的 MinGW-w64 (gcc 13.2、cmake 3.28、ninja), 不需要 MSVC:

```powershell
desktop\scripts\build.ps1
```

- **产物**: 先编到 `desktop/build/dev/bin/` (开发版). 自检只用这一份, 日志在 `build/dev/wmpet.log`, WebView2 数据在 `build/dev/webview2-data/`.
- **发布**: 编译成功后再发布到 `desktop/build/bin/` (你实际用的那份, `start-pet.cmd` 启动它). 那份正在运行时 exe 被占用, 跳过发布并提示.
- **WebView2Loader.dll**: 从 SDK 原样复制, SDK 本身不改.
- **图标** (`host/res/wmpet.rc` -> `host/res/app.ico`, windres 编进 exe): 资源管理器和任务栏里的 exe、桌宠窗口、操作面板窗口、托盘都用它.

## 运行

双击 `desktop\start-pet.cmd` (带 `--services`: 服务端、本机模型、语音没开就在后台开起来, 见下面"本地服务"), 或者在 PowerShell 里 (项目根目录):

```powershell
& .\desktop\build\bin\wmpet.exe --server http://127.0.0.1:8790 --services
```

不带 `--services` 就和以前一样: 要先自己把服务开好.

- **出现在哪**: 主显示器右下角, 站在任务栏上.
- **没有任务栏按钮**, 也不进 Alt+Tab. 只有托盘图标 (可能收在右下角的"^"里), 右键是菜单: 说话、麦克风、隐藏、退出.
- **看不到它时**: 看 `desktop/build/wmpet.log`. 有没有"启动"和"页面就绪"两行, 就知道是没启动起来, 还是页面没加载出来.

- 宿主方式和点穿方式可以选, 默认就是 M0 实测选定的组合: `--host hwnd|comp`、`--ct layered|toggle|plain`.
- 其他选项:
  - `--devtools` 打开开发者工具菜单;
  - `--size 420x800` 设逻辑尺寸;
  - `--memory-level normal` 不把内存目标设成低;
  - `--query "tex=1024&morph=keep"` 临时覆盖页面的省内存选项 (见 `web/pet.js` 开头).
- 日志写到 `desktop/build/wmpet.log`; WebView2 的用户数据放在 `desktop/build/webview2-data/`.
- **连 8790 的真实服务时, 你在桌宠里说的话就是真实对话**, 会进长记忆. 开发和测试一律用自检脚本起的 8794 mock 服务.
- **麦克风**: 托盘"麦克风"打开, 默认关. 说完话停一下就成一轮, 和网页版一样 (服务端要开语音识别).
  - 半双工默认开: 角色说话时上行静音帧, 免得把外放的声音当成插话.
  - 桌宠隐藏、或全屏程序时自动隐身, 都会先停止采音, 显示回来再按开关恢复.
  - 页面要麦克风权限时, 由宿主决定: 只有托盘开着才放行, 其他权限一律拒绝.

## 2D 门面 (Live2D: Eustia)

每个人设预设可以选门面: 3D (VRM, 默认) 或 2D (Live2D). 换了门面, 宿主会带上 `face=live2d` 重新打开页面.
3D 还能选用哪个模型 (2026-10-25): 门面下拉里除了"3D (服务端默认的角色)", `models/vrm/` 里的每个模型各一项 ("3D · silvercat"),
存成 `vrm:文件名`, 宿主打开页面时带 `avatar=文件名` (只认字母数字和 `_ - .`). 列表是面板页面向服务端要的 (`/api/avatars`), 新模型放进去就有.

**用户自己做的模型 Silver Cat Girl** (`models/vrm/silvercat.vrm`, 2026-10-25, 来自 `E:\MyCharaterModels\output
evision_02` 的 VRM 1.0 版):
55 根骨骼 (含手指、脚趾、下巴)、标准表情和口型、双马尾 / 鬓发 / 发带 / 猫耳 / 裙摆 20 条弹簧链. 许可写的是只有作者能用、可以改、不能再分发
(原模型是 Tripo 生成的), 自己用没问题, 要发布先看 Tripo 的条款.
- 动作体检 (`tools/motion_checkup.py --avatar silvercat.vrm`): 身体比例和 miomio、wendy 差不多 (髋高 0.907 m), 26 个场景 x 2 个种子全做成;
  比参照明显差的 4 项是手势和走到门口时单脚站重心出支撑面、把书和球放到沙发上时东西插进骨盆. 报告在 `logs/motion-checkup/`.
- 小屋: 冲咖啡、看书、瑜伽、睡觉、电脑都做成; 坐着骨盆离座面 0.3-0.5 cm, 杯子握住, 盖好被子戳出 60-90 个顶点.
  不太好的: 瑜伽各式负分 (扯到膝盖、树式脚插进小腿), 待机时两条小腿交叠最深 8 cm (比 miomio 多).

**第一次用之前**: 把 SDK 和模型从 `character_models` 的压缩包里取出来 (不用下载任何东西):

```bash
python desktop/scripts/prepare_live2d.py
```

- SDK 放到 `desktop/third_party/live2d/`: Core 原样; Framework 的 TypeScript 用本机 Node 自带的类型去除转成 JS (`strip_ts.mjs`, 只去类型、不改逻辑); 着色器原样.
- Eustia 放到 `desktop/third_party/live2d-models/Eustia/`: 文件名换成英文, 另写一份 `pet-model.json` (表情、动作、情绪对应的表情、做得到的动作).
- **许可**: 只在本机自己用. Core 不能改、不能单独分发、不能传公开仓库; Eustia 没有附许可. 公开发布前要先向 Live2D 申请, 详见路线文档 5.4.

**她能做什么** (`web/live2d-avatar.js`):
- **口型**: 跟着声音动 (有 A2F 时用下巴开合).
- **情绪对应表情**: 开心、兴奋 -> 含情脉脉; 难过 -> 遗憾; 害羞 -> 红温; 生气 -> 皱眉; 惊讶 -> 震惊.
- **头部动作**: 点头、摇头、歪头思考、鞠躬, 用头和身体的角度参数做. 说话时的韵律 (重音点头、挑眉、瞟一眼) 也有.
- **待机**: 眨眼、呼吸、头发和衣服的物理用 Framework 自带的; 空闲时隔 25–45 秒放一段模型自带的动作.
- **跟着鼠标看**: 眼珠 (`ParamEyeBallX/Y`) 和头的角度, 见上面"眼睛跟着鼠标".

## 动作和头发的流畅度

- 空闲帧率默认 30 (原来 10, 用户嫌待机、头发一卡一卡的); 托盘里还能调回 10 / 15 省电. 30 帧时核显约 9.8%, 10 帧约 3.6%.
- 头发、裙子的物理 (`web/springs.js`): `web/avatar-vrm.js` 每帧调 `vrm.update(min(dt, 0.05))`, 10 帧时一帧 0.1 秒只算 0.05 秒 —— 头发按半速慢动作飘, 还一大步一大步地跳. 桌宠这边接管弹簧骨骼的 update: 按真实过了多久算, 拆成每步不超过 1/60 秒 (30 帧时每帧约 2.5 步). 不改 `web/` 的文件.
- **穿模** (用户说腿、头发、衣服穿模严重, 坐在凳子、沙发上尤其明显):
  - 模型自带的碰撞体太小 (miomio 躯干半径 2.9 cm, 实际约 12 cm; 头 3.2 cm), 腿上的碰撞体也没被任何一串头发用上. 桌宠给所有弹簧骨骼补一组身体碰撞体: 头 (球)、胸和腰 (胶囊)、髋 (球)、大腿、小腿、上臂、前臂 (胶囊), 按身高换算 (`bodyColliders`).
  - 坐着、躺着时再加一个"座面": 埋在座面下面的大球, 球顶正好是座面 (`surfaceCollider`), 头发、裙子落在垫子上, 不穿进沙发和床里; 球顶附近接近平的, 往外沿慢慢低下去, 裙摆还能从座位前沿垂下来.
  - 小屋里的座面高度按家具重新量过: 电竞椅 0.58 m、阅读椅 0.48 m、床 0.68 m (原来坐得太低, 腿和屁股陷进坐垫).
  - 屁股陷进座位 (2026-10-25 修了): 自检每秒量"按公式骨盆该在的高度"和实际高度, 坐床沿低 11-17 cm、阅读椅低 10-15 cm, 电竞椅不低.
    差的是行动层的"骨盆补偿": 腿伸直还够不到落脚点时把骨盆往下降, 坐着时落脚点在座位前沿外的地上, 座位高、座位深就够不着.
    `web/locomotion.js` 改成坐着不降, 够不着的落脚点沿座位朝向往回收 (再够不着脚就悬着) —— 这部分是主网页的会话改的, 小屋这边量和回归.
    之后坐稳时骨盆离座面 -0.8 到 +1.7 cm, 不再报"屁股陷进座位里". (先猜是坐着待机换到了骨盆低的坐姿片段: 34 段坐姿髋高都在 0.53-0.69, 不是;
    在小屋这边反馈着改座面高度也试过, 不对症, 撤了.)

## 小屋的性能 (2026-10-27)

用户说"有物理交互的时候小窝很卡". 先量 (`tools/room_perf.mjs`), 再按量出来的改; 详细的做法、数字、试过没留的在知识库「小屋性能实验记录」.

- **量法**: `node tools/room_perf.mjs --plan stand:20,walk:30,coffee,drop:10,spill:12 --rigid 1 --fps 30 --out a.json` (本地代理 + 无界面 Chrome,
  从外面给各层包一层计时, 不改运行代码); `--report a.json,b.json` 出表 (每一段帧耗时 P50/P95/最差、各层均值、次数、GC、分配);
  `--light 1` 只量帧耗时和 GC, `--profile 段` / `--alloc 段` 录 CPU、分配采样, `--gpusync 1` 把 GPU 时间算进来, `--throttle 4` 模拟慢电脑.
- **卡在哪**: 有物理时的大卡顿几乎全是液体落点 (洒出来的每一滴每一小步往下照房间, three.js 照 116 万个三角形一次 15-17 ms,
  洒一股时一帧 500-640 ms); 其次是东西第一次挪进活动层时编译着色器 (100-140 ms 一下). 平时的开销: 弹簧骨 3 ms (慢的一帧会补到 15 步),
  角色整树矩阵每帧重算 9-12 次共 3-4 ms, 行动层 2-3 ms, 接触层 1.5-1.9 ms, 运动学监测 1.5-2 ms, 渲染 2 ms. 刚体本身 (Rapier) 每帧 0.14 ms;
  存储每 4 分钟写 28 次共 29 KB, 不是瓶颈.
- **改了什么** (都带页面参数开关, `perfoff=ray,matrix,spring,warm,node,proxy,puddles`, `perfoff=all` 全关 = 改之前):
  - `room-ray.js` (DownRay): 液体落点往下照, 按网格分格只试竖线经过的三角形, 和 three.js 逐位相同 (对拍 3000 次 + 单测), 一次 16.7 → 0.26 ms.
  - `room-life.js`: 小屋就绪后把房间、活动层的材质按屏幕的画法预编译 (`compileAsync`, 不卡页面).
  - `fast-matrix.js`: 角色根节点的 `updateMatrixWorld(true)` 只重算变了的节点, 逐位相同 (页面对拍 22275 次 + 单测), 每次 0.17-0.28 → 0.10-0.14 ms.
  - `springs.js`: 第二步起不再算弹簧骨的祖先 (逐位相同); 一帧最多 8 步, 电脑慢时按每步实际耗时自动少拆 (一帧最多 10 ms, 但至少 2 步).
    封顶、少拆会改数值 (不是逐位相同), 按阶段评审单独验证过 (知识库记录第 9 项): 录下小屋 75 秒里弹簧骨的全部输入, 回放逐位重现真实页面,
    只换每帧几步, 比头发、裙子 (silvercat、wendy). 菜单里的空闲帧率 (10/15/30/60) 和原来逐位相同, 只有卡了 0.13 秒以上的那一帧、
    切后台回来那一帧少拆 (瞬时最大差 4.7 cm); 慢电脑每帧只走 1 步时头发和 60 帧参考的差是原来的 2.4-3 倍, 至多 2 步时 silvercat 和原来
    差不多、wendy 的长头发仍差一些. 第一版 (最多 4 步、5 ms、可降到 1 步) 用 `springmax=4&springbudget=5&springmin=1` 回到.
  - `room-props.js`: `node()` 记住找到的节点.
  - InverseCache (**最大的一项**): three-vrm 给弹簧骨的中心节点 (Hips) 的 `matrixWorld.elements` 装了一个 Proxy (逆矩阵缓存),
    three.js 的矩阵函数碰过它以后类型反馈被污染, 之后所有矩阵运算写小数都要装箱 (每次乘法 300 字节, 冲咖啡时每秒 8-17 次回收).
    载入模型前换掉 `VRMSpringBoneJoint.prototype.center` 的 setter, 放一个不用 Proxy 的逆矩阵缓存 (结果逐位相同, `perfoff=proxy` 关).
    先做在 `springs.js` 里, 当晚挪到 `web/spring-center.js` 和网页版共用 (`/static/avatar-vrm.js` 一导入就装上, `springs.js` 只导入它),
    网页版的执行评估、端咖啡评测台结果逐位不变、快 2-4 倍 (非独占资源量的), 见根目录 README「网页版也装上弹簧骨逆矩阵缓存」.
- **结果** (刚体开, 轻量模式只量帧耗时, 全关 `perfoff=all` 对全开): 站着 P50 9.6 → 4.6 ms、走路 10.5 → 5.4 ms、冲咖啡 10.9 → 5.2 ms (最差 368 → 46 ms);
  杯子掉下来以后 P95 234 → 8 ms、最差 466 → 13 ms、帧率 17 → 30; 洒一股 P95 273 → 7 ms、帧率 18 → 30; 超过 50 ms 的帧 95 → 0, GC 1479 → 408 次.
  CPU 放慢 4 倍 (模拟慢电脑) 时见知识库记录.
- `room-puddles.js`: 水渍、印子用两张实例化网格画 (湿的、干的各一张; `perfoff=puddles` 换回每摊一个网格), 洒一股时每帧绘制 44 → 27 次.
  印子物理那边不按条数删 (同一处 5 cm 内并成一块), 块数随洒过的不同地方涨; 这里不管多少块都是 2 次绘制, 500 块时每帧 update 0.034 ms. 行动层、接触层、运动学监测和认知事件流的建议已转给对应会话.

**怎么生效**:
- **人设和模型**: 桌宠连上服务端时, 把当前预设发给服务端 (`/ws` 上行 `profile`, 格式见根目录 README; 默认预设不发), 从下一轮起生效.
  - 服务端的回应 (`profile_done`) 不对时, 对话栏会提示"人设预设没生效: 原因".
  - `pet_state` 里能看到当前预设和服务端的回应 (都不带 key).
- **工具** (只有云端模型接, 本地模型不接): 当前预设选了云端模型时, 宿主 (`host/src/tools.cpp`) 去连勾选的 MCP 服务器, 连接常驻.
  - 交给模型的工具: 没禁用的 MCP 工具, 叫 `mcp__服务器名__工具名` (和 Claude Code、dsh 一样); 预设勾了 skill 时再加一个 `load_skill`.
  - 模型要调工具时 (服务端下发 `tool_call`), 按权限办:
    - 自动: 直接调;
    - 每次确认: 对话栏下面弹一张卡片, 写着哪个服务器的哪个工具、参数是什么, 三个按钮"允许一次 / 总是允许 / 拒绝". 30 秒不回答算拒绝; 总是允许会写回设置.
    - 禁用: 根本不交给模型.
  - 调用结果 (或者"用户拒绝了""没有及时确认") 用 `tool_result` 交回服务端, 服务端接着生成回答. 服务端不等了 (`tool_cancel`) 时卡片自己收起.
  - **卡住的调用**:
    - 在调的时候对话栏右边有个"停". 点了宿主马上放弃等待, 给模型回"用户在对话栏里停掉了这次调用".
    - 每个 MCP 服务器在面板里可以设调用超时 (5 到 600 秒, 默认 60), 超过了回"等了 N 秒没有回应".
    - 服务端不等了 (`tool_cancel`, 它等 90 秒) 时, 在调的也停掉 (这时不再回结果).
    - 停掉和超时都会告诉 MCP 服务器 (`notifications/cancelled`), 连接留着接着用, 不重连.
  - `load_skill` 由宿主读那个 skill 的 `SKILL.md` 全文.
  - 只读工具断线 (服务器进程退出) 时重连再试一次; 有副作用的工具不重试, 免得做两遍. 超时不算断线, 不重试.
  - 文字模式 (`wm-text`) 那条连接不接工具 (没有地方问你).
- **审计日志**: 每次调用一行, 写在设置旁边的 `pet-tool-audit.jsonl`: 时间、工具、参数摘要 (最多 300 字)、谁决定的 (`auto` / `once` / `always` / `deny` / `timeout` / `cancelled`)、成没成、结果字数、耗时.

## 本机接口 (OpenAI 兼容 API 和 MCP)

让别的程序把她当成一个聊天模型用, 或者让 AI 助手 (Claude Code、Claude Desktop 等) 把她当成工具用. 默认关:
托盘里勾上"本机接口", 或者启动时加 `--api` (端口默认 8793, `--api-port` 改).

- **只听 127.0.0.1**. 每个请求都要 `Authorization: Bearer <token>`. token 第一次打开时生成, 存在 `%APPDATA%\WorldModel\pet-api-token.txt`, 不进版本库.
- **网页发不进来**: `Host` 必须是 `127.0.0.1:端口` 或 `localhost:端口`; 带了 `Origin` 的, 也必须是本机, 否则回 403 (防 DNS 重绑定).
- **连 8790 时这些也是真实对话**, 会进长记忆, 和你在桌宠里打字一样. 所以 `wm-pet` / `wm-text` 只给你自己的程序用; **别把 AstrBot 这类第三方机器人框架接到它们上**: 它们转来的是别人的话, 会进到带工具的那条对话、改掉你的记忆. 给它们用 `wm-guest` 和访客 token (下面).
- **两个 token, 按 token 定权限** (2026-10-24):
  - 主人的 `pet-api-token.txt`: 下面三个模型和 `/mcp` 都能用;
  - 访客的 `pet-api-guest-token.txt` (同一个文件夹, 第一次打开本机接口时生成): 只有 `wm-guest`, 写哪个 model 都按 `wm-guest` 走, `/v1/models` 只列它, `/mcp` 回 403.

**OpenAI 兼容** (`http://127.0.0.1:8793/v1`):
- 三个模型:
  - `wm-pet`: 桌面上的她来回答. 开口说, 带表情和手势, 对话栏照常显示, 和你跟她的对话共用上下文. 她隐藏着 (或者有全屏程序) 时回 409.
  - `wm-text`: 只回文字, 不出声也不动. 页面另开一条对话, 上下文分开.
  - `wm-guest`: 访客. 走服务端的访客连接 `/guest` (不是 `/ws`): 没有工具、读不到你的记忆、不写记忆. 人设、模型和每天的额度跟 QQ 页的设置走, 没配过 QQ 就是默认人设 + 本地模型. 不出声、不显示; 回复里有你的隐私 (或她选了不说) 时回空串, 结束原因标 `content_filter` (AstrBot 收到 `stop` 加空内容会当成模型出错连问三次, `content_filter` 它不重试). 页面转这类请求时等的是连接事件, 不靠计时器轮询 (桌宠隐藏、全屏游戏时 WebView2 会压页面的计时器, 以前第一句能拖一分多钟).
    - **按什么分会话**: 请求里 OpenAI 的 `user` 字段; 没有 `user` 时认 AstrBot 的请求头 `x-astrbot-conversation-id` (会话号, 记成 `astrbot:<会话号>`; AstrBot 不带 `user`, 它的 `/new` 会换一个会话号, 这边也跟着换一个访客会话); 两个都没有 (比如 AstrBot 给 ChatUI 会话起标题的请求) 就每句单独一个会话、用完就扔, 不和别的没署名的请求共用历史, 日志记在 `外部渠道/api/某人-…` 下.
    - **带了工具**: 请求里有 `tools` / `functions` / `tool_choice` (不是 `none`) 时照常回答, 回复里不会有 `tool_calls`; 宿主日志记一行"wm-guest 请求里带了 N 个工具, 不用", 计数放在 `pet_state` 的 `guest` 里 (`requests`、`with_tools`), 面板 QQ 页提示去对方那边把工具关掉. `wm-pet` / `wm-text` 带了工具也只记日志.
    - 接 AstrBot 的方案见 `docs/roadmap/astrbot-wm-guest.md`; 本机已用启动器装好 AstrBot 4.29.3 并锁好 (`scripts/astrbot_lock.py`), 用法见那篇的"怎么用"一节.
- 只取最后一条 user 消息; system 和之前的历史都不用, 人设、上下文、记忆由服务端管. 支持 `stream`.
- 回复里的扩展字段 `wm` 带这一轮的情绪和动作, 标准客户端会忽略.
- 同一个模型的请求排队, 一个一个来. `wm-pet` 要等她把上一句说完, 才说下一句.

```python
from openai import OpenAI
token = open(r"C:\Users\<你>\AppData\Roaming\WorldModel\pet-api-token.txt").read().strip()
client = OpenAI(base_url="http://127.0.0.1:8793/v1", api_key=token)
for chunk in client.chat.completions.create(model="wm-pet", stream=True, messages=[{"role": "user", "content": "给我讲个故事"}]):
    print(chunk.choices[0].delta.content or "", end="")
```

**MCP**:
- **两种接法**:
  - Streamable HTTP: `http://127.0.0.1:8793/mcp`;
  - stdio: 只会起子进程的客户端用 `wmpet.exe --mcp-stdio`. 它自己读 token, 转发给正在运行的桌宠.
- **协议版本**: 新版和旧版都认.

小屋里的"玩电脑"就是她替你操作电脑: 云端模型通过 Windows-MCP 看屏幕、点鼠标、打字. 设计和取舍见 `docs/roadmap/desktop-pet.md` 的"玩电脑 = 远程操控电脑和手机".

- **怎么接**: 面板 "MCP 服务器" 页点 "+ 操控电脑 (Windows-MCP)", 再在一个用云端模型的人设预设里勾上它. 勾上以后这个预设自动带上随附的 skill `computer-use` (`desktop/skills/computer-use/SKILL.md`, 操作要领; 描述里就写着几条最要紧的, 模型不读全文也看得到).
  - 面板里存的启动参数只开 12 个工具 (`--tools`). 高风险档的 7 个 (执行命令、文件、注册表、进程、剪贴板、抓网页、系统通知) 由宿主起服务器时按设置 `guard.power` (默认开, 面板里服务器下面有个勾) 加上或去掉 (`guard::args`), 不用重新添加服务器.
  - Windows-MCP 起一次要 20 秒上下, 宿主连它时等 90 秒 (新版探测 `server/discover` 也等这么久, 不然它按新版回了、宿主又退回旧版握手, 就连不上).
- **五档** (`host/src/guard.h`): 只读 (自动) / 读屏 (每次确认) / 动手 (每次确认) / **高风险** (每次确认, 见下) / 锁定 (不交给模型: 表里没有的、新版本加的工具).
  - 读屏和动手的确认卡片是 "允许一次 / 这一轮都允许 / 拒绝", 没有"总是允许"; 卡片上写着屏幕上的文字会发给哪家.
  - "这一轮都允许"只管这一轮 (你说下一句、点停、5 分钟后作废). 一轮最多 30 次、5 分钟.
- **高风险档** (2026-10-25 用户: "全部放开, 每次确认"; 原来这 7 个是锁定的): PowerShell 跑命令、FileSystem 读/列/搜/写/复制文件、Registry 读注册表、Process 看进程和按名字关、Clipboard 读写剪贴板、Scrape 抓网页文字、Notification 弹通知.
